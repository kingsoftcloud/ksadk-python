0.8.7 is a review candidate and has not been released. Use release installation commands only after
the GitHub Release and both PyPI distributions have been checked. Python 3.12 remains the minimum;
the companion is the published `@kingsoftcloud/ksadk-web@0.3.18`.

## Validate in an isolated environment

Install a reviewed candidate wheel in a new environment:

```bash
uv venv --python 3.12 .venv-087-candidate
uv pip install --python .venv-087-candidate/bin/python /absolute/path/ksadk-0.8.7-py3-none-any.whl
.venv-087-candidate/bin/agentengine --version
```

Choose either `ksadk` or `agentengine-sdk-python`: both own the same `ksadk` imports. The alias's
`[all]` expansion references its own extras and does not install the primary distribution too.
Distributions include built frontend assets. Models, browsers, and official Provider toolchains
still require configuration for the target environment.

ADK validation covers 1.34.3, the development lock's 2.5.0, and the current default installation's
2.14.0. Wheel installation resolves dependencies again, so candidate checks cover both the locked
environment and the default dependency set, using Python 3.12.

## Preserved and updated behavior

- MCP OAuth declarations travel with builds; tools resolve connections at execution time. Credentials,
  authorization waits, and recovery retain Agent, workspace, call, and host ownership checks.
- LangGraph streaming and replay retain message/part identities, reasoning, tool order, and usage.
  Older Runtimes keep their compatible read paths; failure is not reported as empty history or completion.
- AG-UI and A2UI use pinned official contract resources. Tool, input, and OAuth interactions keep
  distinct identities and recovery boundaries.
- Studio preserves initial drafts, confirmed session URLs, and workspace ownership. DSH probes run
  outside the HTTP event loop. Cancellation cleans up owned models and plugin process groups;
  unknown process visibility keeps conservative cleanup budgets.
- Browser delivery checks retain entry-binding and observation boundaries. An ambiguous entry or
  blocked click remains unverified and does not automatically request a code repair. Screenshots
  and auxiliary pages do not replace verification of the delivered page.
- PostgreSQL startup reuses installed schemas, with compatibility paths for 9.6 and 16. Back up
  existing databases first. Shared storage, multiple replicas, and target-service authorization
  require validation in their actual environments.

Current database defaults include 30 seconds for a complete write, 2 seconds for cleanup, and
45 seconds for a native checkpoint read. These bound database phases, separately from model execution.
Use the current [environment reference](/en/docs/references/environment-variables/) rather than
historical defaults from an older upgrade guide.

## Compatibility and rollback

Existing cloud Agents may keep their original SDK and runtime images. A local SDK upgrade does not
rebuild or deploy them. Native Studio defaults and explicit Managed configurations remain;
see the [0.8.6 upgrade guide](/en/docs/framework/guides/upgrade-0-8-6/).

Back up workspaces and databases. Compare history, approvals, cancellation, and multi-turn replies
between isolated old and new environments. Do not let both versions write to one workspace.
Installing an older wheel does not undo data changes, authorizations, or external effects. Explicitly
reconcile `unknown` outcomes rather than retrying business operations to infer their result.

## Candidate and release

The candidate must pass public preflight, source/artifact audits, clean installation, and applicable
browser/database checks. Passing tests does not authorize publication. Tags, Releases, PyPI packages,
and documentation must trace to the reviewed public `main` commit through protected workflows.


See [0.8.7 Integration and Configuration](/en/docs/framework/guides/integration-0-8-7/) for configuration and integration steps.
