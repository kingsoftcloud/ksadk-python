## Overview

Use this reference to build an Agent chat interface: initialize capabilities, manage sessions, read history, run conversations, resume execution, handle interactions, access files, submit feedback, and complete MCP OAuth authorization. Optional file-preview and native-terminal endpoints are documented separately.

Paths are relative to the Agent access URL supplied by the service. Read the capabilities first and use only features declared by the current deployment.

## Requests and authentication

| Item | Convention |
| --- | --- |
| Base URL | Use the access URL provided by the Agent service |
| Authentication | Automation clients supply Authorization: Bearer API_KEY as required by the service; browser clients may use an established access session |
| JSON | Content-Type: application/json |
| Streaming | Accept: text/event-stream and Stream=true where required |
| Upload | multipart/form-data; the HTTP client generates the boundary |
| Field names | JSON and query parameter names are case-sensitive |

AgentId, UserId, and SessionId locate resources but do not grant authorization. Request, session, invocation, run, checkpoint, and model-response IDs have distinct meanings and are not interchangeable.

## Responses and errors

Ordinary JSON Actions use this success envelope:

```json
{"Code":0,"Message":"Success","RequestId":"req-example","Action":"CreateSession","Data":{"Session":{"SessionId":"session-example","AgentId":"agent-example","UserId":"user-example"}}}
```

Data depends on the operation. MCP OAuth success responses do not guarantee RequestId or Action. Downloads return raw bytes; SSE is an incremental event stream rather than one JSON response.

| Result | Client handling |
| --- | --- |
| HTTP 400 / 422 | Check fields, types, bounds, and field combinations |
| HTTP 401 / 403 | Re-establish a valid access session or correct permissions; do not blindly replay operations |
| HTTP 404 | Check identifiers, ownership, and whether the feature is enabled |
| HTTP 409 | Refresh revision or history state; changing an idempotency key is not a safe automatic retry |
| HTTP 429 | Handle rate or queue limits using the service retry guidance |
| HTTP 503 / 504 | Retry eligible reads; establish the outcome of a write before repeating it |
| HTTP 200 with Code other than 0 | Treat as a business failure and inspect Message, ReasonCode, or detail |

Errors may use Message, ReasonCode, detail, or error. An expired browser access session can also produce an HTML 401/403 response; do not treat it as normal API JSON.

## Initialization

### Get UI capabilities

`POST /agentengine/api/v1/GetAgentUiBootstrap`

Initialize the client with Agent identity, available chat transports, history, recovery, file, OAuth, and terminal capabilities.

| Parameter | Location | Type | Required | Default | Description |
| --- | --- | --- | --- | --- | --- |

## Conversations and runs

### Run an Agent

`POST /agentengine/api/v1/RunAgent`

Execute a conversation turn synchronously, as SSE, or in a supported background mode.

| Parameter | Location | Type | Required | Default | Description |
| --- | --- | --- | --- | --- | --- |
| `AgentId` | body | `string` | Yes | `—` | Target Agent identifier. |
| `Messages` | body | `array<object>` | No | `[]` | Message array containing role and content. |
| `UserId` | body | `string / null` | No | `"user"` | Logical user identifier; authorization is still enforced by the authenticated identity. |
| `AccountId` | body | `string / null` | No | `null` | Account correlation identifier; not an authentication credential. |
| `SessionId` | body | `string / null` | No | `null` | Session identifier. |
| `InvocationId` | body | `string / null` | No | `null` | Invocation identifier used for event subscription and cancellation. |
| `ApiFormat` | body | `string` | No | `"responses"` | Output format: responses or chat_completions. |
| `Stream` | body | `boolean` | No | `false` | Request SSE output. |
| `Background` | body | `boolean` | No | `false` | Request background execution when supported. |
| `Model` | body | `string / null` | No | `null` | Model identifier selected from the model catalog. |
| `ModelMetadata` | body | `object / null` | No | `null` | Model capability metadata. |
| `ModelOptions` | body | `object / null` | No | `null` | Inference options supported by the selected model. |
| `Metadata` | body | `object / null` | No | `null` | Additional request metadata; it does not grant identity or permissions. |
| `ResponsesInput` | body | `JSON value / null` | No | `null` | Responses-style input, including multimodal or continuation input. |
| `PreviousResponseId` | body | `string / null` | No | `null` | Identifier of the preceding Responses response. |

Example request:

```json
{"AgentId":"agent-example","SessionId":"session-example","InvocationId":"inv-example","Messages":[{"role":"user","content":"Hello"}],"ApiFormat":"responses","Stream":true}
```

**Response:** A synchronous foreground call wraps a Responses or Chat Completions result in Data. Streaming branches return SSE. See execution modes below.

For ordinary foreground streaming set Stream=true. Use Background=true only when the service declares support. Messages and ResponsesInput follow the selected input protocol; continuation input may also require PreviousResponseId. Disconnecting HTTP does not itself cancel a run; use CancelRun to stop it.

| Execution mode | Response |
| --- | --- |
| Synchronous foreground | JSON Action; Data contains a model response |
| Streaming foreground | SSE, including possible failure or interaction-wait events |
| Background returning a handle | JSON Action; Data contains SessionId, InvocationId, Status, Background, SubscribeUrl |
| Kernel-admitted streaming or background | SSE using Responses event projection; a JSON handle is not guaranteed |

### Submit an interaction

`POST /agentengine/api/v1/SubmitInteraction`

Submit an approval, rejection, structured answer, or cancellation decision.

| Parameter | Location | Type | Required | Default | Description |
| --- | --- | --- | --- | --- | --- |
| `AgentId` | body | `string` | Yes | `—` | Target Agent identifier. |
| `UserId` | body | `string / null` | No | `null` | Logical user identifier; authorization is still enforced by the authenticated identity. |
| `SessionId` | body | `string` | Yes | `—` | Session identifier. |
| `RunId` | body | `string` | Yes | `—` | Run identifier. |
| `InteractionId` | body | `string` | Yes | `—` | Identifier of the pending interaction. |
| `ExpectedRevision` | body | `integer` | Yes | `—` | Current interaction or authorization-wait revision. minimum 1. |
| `InteractionAction` | body | `string` | Yes | `—` | Decision: approve, reject, submit, or cancel. allowed approve, reject, submit, cancel. |
| `Response` | body | `JSON value` | No | `null` | Any valid JSON value; structured submission must explicitly include this field. |
| `IdempotencyKey` | body | `string` | Yes | `—` | Idempotency key; keep it unchanged when retrying the same submission. minLength 1; maxLength 256. |

Example request:

```json
{"AgentId":"agent-example","SessionId":"session-example","RunId":"run-example","InteractionId":"interaction-example","ExpectedRevision":1,"InteractionAction":"approve","Response":null,"IdempotencyKey":"interaction-example-approve"}
```

**Response:** Data is a command receipt with schema_version, command_id, status, and conditionally message_id, run_id, accepted_seq, or error.

This compatibility endpoint requires an active local Kernel; hosted deployments use their authorized interaction ingress. InteractionAction accepts approve, reject, submit, or cancel. Action is also accepted as a compatibility decision field. submit must explicitly include Response, including when its value is null. Use the current ExpectedRevision and preserve IdempotencyKey on retries. An accepted receipt can return HTTP 202 and a duplicate HTTP 200; accepted/duplicate means admitted, not fully executed.

## MCP OAuth

Use these operations only when the service advertises MCP authorization. Local and hosted authorization state is not interchangeable. The service manages credentials; do not send secrets or access tokens as chat messages.

| Method and path | Purpose |
| --- | --- |
| `POST /agentengine/api/v1/GetMcpAuthorizationWait` | Read the current authorization wait and its permitted actions. |
| `POST /agentengine/api/v1/OpenMcpAuthorization` | Obtain the browser authorization URL for a pending MCP connection. |
| `POST /agentengine/api/v1/RetryMcpAuthorization` | Restart authorization after a failed or denied attempt when allowed. |
| `POST /agentengine/api/v1/RetryMcpConnection` | Retry the connection while valid credentials are still available. |
| `POST /agentengine/api/v1/CancelMcpAuthorizationWait` | Cancel the wait and prevent a late callback from continuing that wait. |

All five operations accept these fields:

| Parameter | Location | Type | Required | Default | Description |
| --- | --- | --- | --- | --- | --- |
| `WaitId` | body | `string` | Yes | `—` | Current MCP authorization-wait identifier. minLength 1; maxLength 64. |
| `ExpectedRevision` | body | `integer / null` | No | `null` | Current interaction or authorization-wait revision. minimum 1. |
| `AgentId` | body | `string / null` | No | `null` | Target Agent identifier. |
| `SessionId` | body | `string / null` | No | `null` | Session identifier. |
| `IdempotencyKey` | body | `string / null` | No | `null` | Optional compatibility field. This group checks state using ExpectedRevision and does not promise deduplication by this field. |

Query example:

```json
{"WaitId":"wait-example","AgentId":"agent-example","SessionId":"session-example"}
```

For open, retry, or cancel, pass the revision obtained from the current state:

```json
{"WaitId":"wait-example","ExpectedRevision":1,"AgentId":"agent-example","SessionId":"session-example"}
```

| Data field | Type | Meaning |
| --- | --- | --- |
| wait_id / run_id / config_id | string | Wait, run, and connection identifiers |
| revision | integer | Current revision for subsequent operations |
| status | string | Current authorization/connection state |
| display_name | string | MCP service display name |
| scopes | string[] | Requested authorization scopes |
| allowed_actions | string[] | Actions currently permitted |
| requires_resume | boolean | Whether continuation is associated with the wait |
| deadline | number | Wait deadline in Unix seconds |
| error | string / null | Failure reason |
| authorization_url | string, optional | Browser URL returned by OpenMcpAuthorization |

allowed_actions values query, open, retry_authorization, retry_connection, and cancel correspond to the five operations above. Perform only currently permitted actions. Refresh state after the browser completes actual authorization. A cancelled wait must not be completed by a late callback. A state conflict can return HTTP 409 with ReasonCode; refresh before deciding the next action.

## SSE conventions

Use an incremental HTTP reader and split frames on blank lines. One network chunk is not one JSON object. Lines beginning with a colon are comments/heartbeats. SubscribeRunEvents data frames contain events and [DONE] ends that subscription. Non-Kernel RunAgent streams follow ApiFormat; Kernel streams use named Responses events such as response.completed, response.failed, and response.canceled. An interaction can produce response.incomplete and close the foreground stream; connection closure is not necessarily success. Parse AG-UI streams according to AG-UI.

Reconnect using the same SessionId, InvocationId, and the last confirmed AfterSeqId. Do not replay user input to simulate continuation. HTTP 200 alone does not mean the streamed run succeeded.

## Optional file previews and local native terminals

Use these endpoints only when enabled. Native terminals are not a generic remote shell for every hosted user.

### File preview resource

`GET /_ksadk/workspace/v1/files/{file_path}`

file_path is relative to the workspace and may contain multiple segments. URL-encode segments separately. Render returned bytes using Content-Type; HTML previews can resolve their relative assets through the same workspace path.

### Create or reuse a terminal session

`POST /_ksadk/terminal/sessions`

| Parameter | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| session_id | string | No | empty | Associated chat session |
| mode | string | No | tui | Terminal mode supported by the runtime |
| cols / rows | integer | No | 80 / 24 | Terminal dimensions |
| force_new | boolean | No | false | Force a new terminal session |
| cwd | string | No | unspecified | Working directory subject to runtime restrictions |

```json
{"session_id":"session-example","mode":"tui","cols":80,"rows":24,"force_new":false}
```

Returns `{"session":{...}}`. Use terminal_session_id from that object for attachment and closure.

### List terminal sessions

`GET /_ksadk/terminal/sessions`

Optional query fields session_id and mode filter the result. Returns `{"sessions":[...]}`.

### Close a terminal session

`DELETE /_ksadk/terminal/sessions/{terminal_session_id}`

Returns deleted and terminal_session_id. A missing session can return HTTP 404.

### Attach terminal WebSocket

`WS /_ksadk/terminal/ws?terminal_session_id=<TERMINAL_SESSION_ID>`

Use WSS for a remote secure connection and negotiate Sec-WebSocket-Protocol: ks-terminal.v1. The terminal identifier comes from session creation. Stop on a capability or identity denial; do not attempt to bypass authorization.
