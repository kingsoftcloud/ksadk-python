## 3. Codex Runtime 瘦身

第一阶段边界如下：

- Server 负责插件准入、制品归属、KS3 元数据和短期凭证。
- Runtime Service 负责把可选插件制品配置投影到 AgentRuntime CR。
- Operator 负责 Pod 编排、init container 下载、校验和挂载。
- KsADK Runtime 只验证并加载已物化的本地插件目录。
- Codex Provider 插件只保留 Codex 生命周期、审批、会话和协议适配，不承担平台控制面、KS3 下载或资源治理。

发布门禁：

- [x] 删除运行时对 Server/KOP 插件下载接口的依赖。
- [x] 未绑定插件的 Agent 不创建插件下载配置，原有代码 Bundle 路径保持兼容。
- [x] Container Runtime 可携带辅助插件制品，不改变运行镜像和工作目录。
- [x] 插件目录拒绝符号链接、额外文件、缺失文件和摘要不一致。
- [x] Studio 注入的 RuntimeExecutor 贯穿 Codex AgentProvider，Provider 不创建第二条默认 Codex 执行链。
- [x] DSH 注册探测使用有界进程；每个 PluginHost 在自己的事件循环创建、校验并持有执行 sidecar。
- [ ] 记录瘦身前后的 Runtime 依赖、职责和关键代码量，更新架构文档。

## 4. Studio 功能与视觉统一

### 会话

- [ ] 新会话不展示旧 Run 的检查器内容，标题在首条消息后生成可读名称。
- [ ] 对话正文使用合理最大宽度，在宽屏居中并保留足够内容空间。
- [ ] Markdown 表格、列表、代码和长工具名在桌面与窄窗口中不溢出、不挤压。
- [ ] 工具调用使用统一事件行；模型正文中的普通行内代码不渲染成高对比按钮框。
- [ ] 输入区、正文、运行检查器对齐，空白和层级使用统一间距变量。

### Agent 与资源

- [ ] Runtime 不支持 Tool 绑定时隐藏整个 Tool 区域。
- [ ] 知识库、记忆库和 Skill Center 使用统一绑定组件并显示真实名称与来源。
- [ ] 资源搜索框图标、占位文字和输入文字不重叠。
- [x] 插件页提供“全部 / KSADK 官方 / DSH / Codex”等来源筛选。
- [ ] DSH 插件只有声明可挂载的设置页或工作区时才显示入口，不制造空白侧栏 Tab。

### 构建、部署、自动化与可观测

- [ ] 构建列表明确显示 Agent、Revision、制品类型、时间和状态，并提供“去对话 / 去部署 / 查看详情”。
- [ ] 从具体 Agent 或 Build 进入部署页时自动锁定上下文，不要求重新猜选同名 Build。
- [ ] Trace 列表分页；关键路径、首 token、模型等待、工具耗时和空档期可读。
- [ ] 自动化页面体现新版看板、状态分组、下一次运行和失败入口。
- [ ] 页面统一颜色、字体层级、边框、圆角、密度、空状态、加载态和错误态。
- [ ] 以 1440px、1920px 和常用窄窗口完成浏览器截图验收。
