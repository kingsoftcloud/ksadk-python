# Studio 云端插件交付实施计划

状态：待实现，不代表云端插件已可用。2026-09-07。

## 当前事实与目标

本地安装属于工作区；AgentRevision 的绑定决定使用哪些插件组件，Build 锁定对应版本和摘要。当前 Codex ManagedRuntime 部署只发送 YAML，不上传工作区插件快照，因此已有云端 Agent 不会自动拥有本地插件。新代码已阻止带原生插件绑定的 YAML 静默降级部署；这项保护不等于完成交付。

完成标准：同一 Build 的本地运行与全新云端实例加载相同插件组件集合；已授权的远程 MCP 至少成功执行一次只读调用；重启、扩容、升级、回滚均能恢复声明的插件版本。没有凭证时明确显示待授权，不报告已就绪。

## 职责和交付协议

- `ksadk-python`：收集 Build 已验证的插件字节、生成清单、上传制品、运行前下载校验和恢复。不能依赖开发机绝对路径。
- `agentengine-server`：接受和授权制品引用，绑定 AgentVersion，记录交付状态；向运行实例提供短期下载权限及凭证引用。
- `agentengine-images` / 运行服务：提供声明支持的 Codex/DSH/Node 版本、可写状态目录、启动门禁和错误投影。
- `ksadk-web` / Studio：展示已安装、已绑定、已交付、待授权、可调用这些不同状态，以及缺失原因。

建议新增 `pluginArtifacts` 作为 AgentVersion 的版本化字段。字段名为提案，必须完成控制面 schema 评审、能力协商和客户端/服务端契约测试后启用，当前 API 不支持它。

每个引用包含：生态、精确 pluginRef、snapshotDigest、artifactDigest、授权域内的 artifactId、格式版本、选定 components、所需 runtime 版本。摘要参与 AgentVersion 内容标识。长期存储 artifactId，不能把有期限的签名 URL 当不可变清单内容。

制品内容只包含被选定版本的插件源码/资源、manifest、组件索引、依赖锁与必要运行资产。排除 auth.json、.credentials.json、.env、浏览器状态、历史会话和任意工作区文件。制作清单时按白名单收集；不能递归打包整个 CODEX_HOME 或整个 DSH profile。

安装后不同生态的执行方式保持不变：Codex 通过已验证的本地 marketplace 安装；DSH 在同一个完整官方 Core/profile 中恢复。不能引入第二个 DSH 宿主或 mini runtime。跨 harness 只复用明确可移植的 MCP/Skill 贡献，Codex 专用 App/宿主能力不能虚报通用兼容。

## 实施顺序和验收

### C1：确定性插件制品

在 SDK 中从不可变 Build 锁生成插件归档和索引；相同输入得到相同摘要。复用现有 snapshot 校验和安装机制，不重新实现插件解析器。

验收：离线临时工作区可以还原组件；非法路径、符号链接逃逸、超限归档、摘要不符被拒绝；扫描证明没有凭证；修改源工作区不改变已冻结制品。

### C2：控制面制品引用

在 Server 现有上传/对象存储流程中添加插件制品类型和 AgentVersion 引用，按工作区/租户鉴权。增加明确的服务器能力标志：旧 Server 未声明支持时 SDK 在上传前拒绝插件部署。

验收：Create/Update 保留相同引用；幂等重试不会生成重复 Agent 或丢绑定；跨租户引用被拒绝；不把插件字节塞进 YAML/ConfigMap，不突破现有 manifest 大小限制。

### C3：云端启动恢复

运行时依据 artifactId 获取短期下载地址，在临时目录下载、校验和安装，完成后原子切换。校验清单、依赖和组件成功前不发布插件 Ready。插件失败必须有可定位的阶段和错误码，不能继续以“无插件 Agent”运行。

验收：全新空盘容器可以运行；Pod 重启/扩容和下载重试可恢复；旧版本回滚恢复旧插件摘要；DSH Core 和 Codex 的版本不一致时明确拒绝启动，不临时漂移升级。

### C4：授权与工具就绪

授权绑定至少包含用户/工作区、Agent、MCP 服务名、规范化服务地址和权限范围。浏览器回调完成后，服务端保存授权结果、刷新对应工具列表，Studio 展示可调用状态。仅安装 Skill 不得推断工具可调用。

云端凭证通过 Secret/受限凭证代理提供，独立于插件制品。不得把桌面 OAuth refresh token 随镜像或归档上传。不同用户、不同 Agent、不同服务地址不得自动继承授权。ChatGPT Apps 和直接 MCP OAuth 是不同授权路径，分别检测。

本地当前补充：同一 Agent 的新 Build 可复用相同已绑定 MCP 服务的本地 OAuth grant；该机制不代表可向云端复制凭证，也不等同于完整的授权管理服务。仍需接入可撤销、可观察的授权生命周期。

验收：真实远程 MCP 在云端成功执行一次只读调用；未授权和过期可刷新/重新授权；关闭授权后停止提供相应工具；不存在把“资源列表为空”等同“工具列表为空”的判断。

### C5：真实用户场景与旧部署升级

先用隔离验收 Agent 跑 C1–C4，再对用户选择的既有部署生成可审核的新 AgentVersion。已有镜像和 YAML 不会因本地升级自动获得插件；必须显式部署新版本。

验收记录包括：Build/AgentVersion、插件摘要、运行时版本、Pod 镜像及 imageID、恢复状态、工具清单和只读调用结果。执行前后对照相同绑定集合。保留旧 AgentVersion 和制品以便回滚。

## 进度与时间口径

C1–C5 当前未完成，不能承诺本轮即可发布。优先交付一个 Codex 插件的全新云端实例闭环，再扩展 DSH 和其他 harness 的矩阵。完成 C1/C2 并确认预发镜像、制品存储、Server 能力可用后，才有依据评估剩余联调时间。

发版条件：云端交付和授权闭环通过上述验收，再运行仓库既有 preflight/公开候选 review。不能以本地技能可见、单测通过或仅增加部署阻断提示，替代云端验收。
