# Studio 云端插件交付实施计划

状态：待实现，不代表云端插件已可用。2026-09-07。

## 文档范围与共同约束

本文定义各类插件共用的云端制品、控制面引用、启动恢复和授权交付合同。[KsADK Studio 平台资源插件研发设计](studio-platform-resource-plugins-design.md)在此基础上定义知识库、记忆库、Skill 的业务绑定、Python Worker、运行 scope 和执行器适配。

- 云端制品和授权交付以本文为准；资源语义和 scope v2 以资源插件设计为准。两者共享同一个 Build，不另建资源插件专用上传服务、授权库或 MCP 宿主。
- 官方能力以插件交付；预装仍遵守版本锁定和生命周期。身份、Secret、审批与审计属于可信宿主。
- DSH 每个 profile generation 只有一个完整官方 Core，复用其 HTTP/MCP 服务。不同隔离 profile 可以各有 Core，同一 profile 不得双宿主。
- 新字段、状态和验收项均为待实现合同；文档对齐不代表 API 或云端能力已上线。

## 当前事实与目标

本地安装属于工作区；AgentRevision 的绑定决定使用哪些插件组件，Build 锁定对应版本和摘要。当前 Codex ManagedRuntime 部署只发送 YAML，不上传工作区插件快照，因此已有云端 Agent 不会自动拥有本地插件。新代码已阻止带原生插件绑定的 YAML 静默降级部署；这项保护不等于完成交付。

完成标准：同一 Build 的本地运行与全新云端实例加载相同插件组件集合；已授权的远程 MCP 至少成功执行一次只读调用；重启、扩容、升级、回滚均能恢复声明的插件版本。没有凭证时明确显示待授权，不报告已就绪。

2026-09-07 补充核对基线为 `ksadk-python` 本地提交 `beea4ed5b76f65b675c8808c219737e54b954c3f`，不代表远端最新。相关入口为 [YAML 部署门禁](../ksadk/studio/cloud.py)、[本地 OAuth grant 复用](../ksadk/studio/codex_credentials.py)和 [Codex Run](../ksadk/studio/codex_run.py)。本次仅核对并完善文档，没有重新执行云端部署验证。

## 职责和交付协议

- `ksadk-python`：收集 Build 已验证的插件字节、生成清单、上传制品、运行前下载校验和恢复。不能依赖开发机绝对路径。
- `agentengine-server`：接受和授权制品引用，绑定 AgentVersion，记录交付状态；向运行实例提供短期下载权限及凭证引用。
- `agentengine-images` / 运行服务：提供声明支持的 Codex/DSH/Node 版本、可写状态目录、启动门禁和错误投影。
- `ksadk-web` / Studio：展示已安装、已绑定、已交付、待授权、可调用这些不同状态，以及缺失原因。

### 同一个 Build 的声明与制品

建议新增 `pluginArtifacts` 作为 AgentVersion 的版本化字段。字段名为提案，必须完成控制面 schema 评审、能力协商和客户端/服务端契约测试后启用，当前 API 不支持它。

每个引用包含：生态、精确 pluginRef、snapshotDigest、artifactDigest、授权域内的 artifactId、格式版本、选定 components、所需 runtime 版本。摘要参与 AgentVersion 内容标识。长期存储 artifactId，不能把有期限的签名 URL 当不可变清单内容。

| 对象 | 权威来源与作用 | 云端处理 |
| --- | --- | --- |
| AgentRevision 插件 binding/config | 声明选择的组件、资源引用和策略 | Build 冻结；运行中不回读最新草稿 |
| Build 的 binding snapshot / plugin lock / skill lock | 固定声明、插件及 pinned Skill 的版本和摘要 | 生成统一制品索引，绑定 AgentVersion；资源插件不另建发布真相 |
| `pluginArtifacts`（拟议） | 记录上述插件制品的引用、摘要和兼容性要求 | Server 持久化并鉴权；runtime 下载、核验与恢复 |
| `ComponentConfig` | 既有高代码资源引用，或由完整绑定生成的兼容投影 | 校验与 Build 一致，不能代替插件制品或完整资源策略 |
| 授权/凭证引用 | 独立的授权服务、Secret 或受限代理 | 激活时解析并重验权限；凭证值不进入 Build/归档 |

语义 Build digest 基于规范化声明和内容摘要，不包含上传后产生的 artifactId；AgentVersion 记录 Build 身份与制品引用。重传同一内容不改变插件版本，下载 URL 续期不改变 Build 或 AgentVersion 内容身份。物理存储键不作为插件内容身份；具体字段、规范化算法及幂等合同在 C1/C2 固定。

制品内容只包含被选定版本的插件源码/资源、manifest、组件索引、依赖锁与必要运行资产。排除 auth.json、.credentials.json、.env、浏览器状态、历史会话和任意工作区文件。制作清单时按白名单收集；不能递归打包整个 CODEX_HOME 或整个 DSH profile。

依赖锁本身不保证离线可恢复。C1 必须证明运行所需字节已包含在制品或声明的不可变基础镜像中；缺少依赖时构建/部署拒绝，不能在启动阶段临时解析浮动版本。目标 OS、架构和原生依赖兼容性进入恢复校验。

资源插件的 pinned Skill 使用同一制品索引关联锁定包，保留完整 SKILL.md、声明的脚本/资源和依赖；不能只打包 description。Skill 内容是否允许复制到目标云环境仍需权限校验。discovery 只锁定空间与策略，实际选包在运行时下载、校验并记录 receipt，不承诺离线发现或随 Build 回滚动态内容。知识库正文、记忆记录不随插件制品复制。

### 镜像、插件与执行器的边界

基础镜像锁定运行时和基础依赖，例如 Python SDK、Node、DSH Core、Codex 及 Worker 协议；具体包含哪些运行时由能力矩阵声明。Build 制品锁定选中的插件与必要资产。镜像预装插件可作为摘要匹配的缓存，不能覆盖 Build 版本，也不要求每次插件更新都重建基础镜像；新增不兼容原生依赖时需发布相应镜像。

安装后不同生态的执行方式保持不变：Codex 通过已验证的本地 marketplace 安装；DSH 在同一个完整官方 Core/profile 中恢复。不能引入第二个 DSH 宿主或 mini runtime。跨 harness 只复用明确可移植的 MCP/Skill 贡献，Codex 专用 App/宿主能力不能虚报通用兼容。

| 交付组合 | 必须具备的运行路径 | 不能替代的验收 |
| --- | --- | --- |
| Codex 消费 Codex 原生插件 | 对应 Codex runtime、marketplace 恢复和组件授权 | 不能代表 DSH 插件已支持云端 |
| Codex/LangGraph 消费 DSH 平台资源插件 | 单 DSH Core + 资源插件 + Python Worker/IPC + MCP 执行器适配 | 真实 KB 检索、记忆和 Skill 回合，以及 binding/scope 隔离 |
| DSH 执行器消费平台资源插件 | 执行器所属 Core/profile + 同一资源 Worker 与授权合同 | 原生工具上下文、Provider hook、取消与撤销 |

因此，“先验证一个 Codex 原生插件”是公共交付的首个纵切，不能作为资源插件云端完成条件。资源插件即使由 Codex 调用，仍依赖 C3 的 DSH 恢复路径。

### 状态与失败语义

状态按对象分别存储和展示，不能用一个 ready 布尔值覆盖全流程。以下名称为拟议领域状态，实际 API 枚举在 C2/C4 固定。

| 对象 | 需要区分的状态 | 证据 |
| --- | --- | --- |
| 工作区插件与 Agent binding | 已安装/已启用；已绑定/待构建/待应用 | 安装 receipt、revision 和 Build |
| 云交付 | 待交付/恢复中/已交付/交付失败 | AgentVersion、制品摘要、当前实例恢复 receipt |
| 上游授权与资源验证 | 待授权/授权过期/已撤销/无权限/验证通过 | 当前主体、授权范围和验证时间 |
| 工具与运行 | 可调用/不可用；启动中/active/degraded/failed | 工具清单、只读验证与 activation |

已交付表示声明的组件与依赖已恢复，不等于业务已授权；可调用必须再通过当前权限和能力检查。状态包含 Build、AgentVersion、activation（存在时）、实例、observedAt 与失败阶段，不能用旧 Pod 的成功覆盖新实例失败。

Build 声明的插件制品恢复失败必须阻止该运行激活，不能丢弃插件继续启动。资源设计的 `binding.required=false` 仅允许插件正确恢复后，对可选资源的鉴权/可用性失败显式降级：移除对应工具、停用相关 hook 并展示原因；必需资源失败不进入 active。

旧高代码部署可沿已有能力运行。带原生插件绑定的 Build 不得通过删去 binding、仅留下资源 ID 绕过部署门禁；兼容转换必须显式生成新 revision/Build，展示语义差异并重新校验，不能原地伪装成同一 Build。当前 Codex YAML 门禁在完整交付能力验收前继续保留。

## 实施顺序和验收

### C1：确定性插件制品

在 SDK 中从不可变 Build 锁生成插件归档和索引；相同输入得到相同摘要。复用现有 snapshot 校验和安装机制，不重新实现插件解析器。

验收：离线临时工作区可以还原组件；非法路径、符号链接逃逸、超限归档、摘要不符被拒绝；扫描证明没有凭证；修改源工作区不改变已冻结制品。

离线恢复使用声明的目标基础镜像或等价锁定环境，验证必要依赖闭包、组件选择与 pinned Skill 脚本/资源；记录 snapshotDigest、artifactDigest、运行时要求和恢复结果。

### C2：控制面制品引用

在 Server 现有上传/对象存储流程中添加插件制品类型和 AgentVersion 引用，按工作区/租户鉴权。增加明确的服务器能力标志：旧 Server 未声明支持时 SDK 在上传前拒绝插件部署。

验收：Create/Update 保留相同引用；幂等重试不会生成重复 Agent 或丢绑定；跨租户引用被拒绝；不把插件字节塞进 YAML/ConfigMap，不突破现有 manifest 大小限制。

SDK 发出版本化引用及 Build 内容身份，Server 校验后返回持久引用与交付状态；旧 Server/未知格式/未支持生态或运行时组合在上传前预检拒绝，Server 写入端再做权威校验。新字段名、响应和错误码进入契约测试，不以现有 API 已支持为前提。留存中的 AgentVersion 所引用制品不得被清理，删除策略与回滚保留期共同评审。

### C3：云端启动恢复

运行时依据 artifactId 获取短期下载地址，在临时目录下载、校验和安装，完成后原子切换。校验清单、依赖和组件成功前不发布插件 Ready。插件失败必须有可定位的阶段和错误码，不能继续以“无插件 Agent”运行。

验收：全新空盘容器可以运行；Pod 重启/扩容和下载重试可恢复；旧版本回滚恢复旧插件摘要；实际 DSH Core、Codex、Python/Node 或 Worker 协议不满足 Build 声明的兼容矩阵时明确拒绝启动，不临时漂移升级。这里不要求不同产品的版本号彼此相同。

C3 分别记录 Codex 原生恢复和 DSH 恢复的通过状态。DSH 资源路径还需验证 supervisor 拥有 IPC broker、一个 profile 只有一个 Core、Worker 从可信凭证引用构造实例、消费者使用云端实际 endpoint。localhost/开发机目录不得作为可迁移地址上传。

### C4：授权与工具就绪

对于远程 MCP，授权绑定至少包含用户/工作区、Agent、MCP 服务名、规范化服务地址和权限范围。浏览器回调完成后，服务端保存授权结果、刷新并验证对应工具列表，通过后 Studio 才展示可调用状态。仅安装 Skill 不得推断工具可调用。

云端凭证通过 Secret/受限凭证代理提供，独立于插件制品。不得把桌面 OAuth refresh token 随镜像或归档上传。不同用户、不同 Agent、不同服务地址不得自动继承授权。ChatGPT Apps 和直接 MCP OAuth 是不同授权路径，分别检测。

本地当前补充：同一 Agent 的新 Build 可复用相同已绑定 MCP 服务的本地 OAuth grant；该机制不代表可向云端复制凭证，也不等同于完整的授权管理服务。仍需接入可撤销、可观察的授权生命周期。

上游授权与资源插件的 scope v2 分层：授权服务管理访问服务的资格和凭证引用，runtime 基于该授权为具体 Build/activation/binding 签发短期能力租约。每次激活重新校验授权；同一 Agent 的新 Build 只在主体、服务和权限约束仍匹配时复用有效 grant，始终创建新 scope，不从制品恢复旧 token。不同权限需求需重新校验或授权，不能靠复用 grant 扩权。

知识库、记忆库的托管凭证/STS 复用同一主体与撤销合同，不强制转换为 OAuth。配置中的 connectionRef 不是授权证明，也不意味着整个工作区共享业务权限。服务地址规范化需保留租户、路径等授权边界，具体算法和变更行为在 C4 固定。

授权撤销由控制面向运行时失效通知/有界重验传播，清除工具暴露并撤销相关 scope；不能仅等下一次 tools/list。C4 必须确定传播时限、失联时拒绝策略并验证。已返回文本无法收回，高敏资源撤销还需终止会话、清理其拥有的工作目录。

验收：真实远程 MCP 在云端成功执行一次只读调用；未授权和过期可刷新/重新授权；关闭授权后停止提供相应工具；不存在把“资源列表为空”等同“工具列表为空”的判断。

另覆盖新 Build 合法 grant 复用但旧 scope 不复活、跨 Agent/主体/服务拒绝继承、授权与资源范围变化、必需资源阻断和可选资源显式降级。资源写入和 Skill 执行另走工具审批，不能由 OAuth 成功推断已获执行批准。

### C5：真实用户场景与旧部署升级

先用隔离验收 Agent 跑 C1–C4，再对用户选择的既有部署生成可审核的新 AgentVersion。已有镜像和 YAML 不会因本地升级自动获得插件；必须显式部署新版本。

验收记录包括：Build/AgentVersion、插件摘要、运行时版本、Pod 镜像及 imageID、恢复状态、工具清单和只读调用结果。执行前后对照相同绑定集合。保留旧 AgentVersion 和制品以便回滚。

资源插件发布按资源设计的 A21–A26 和真实业务回合追加验收。回滚恢复插件、绑定策略及 pinned Skill 字节；不会回滚知识库/记忆数据、恢复已撤销授权，或复活旧 scope。discovery 的动态内容按当次 receipt 记录。

## 与资源插件任务的依赖

| 资源任务 | 共同合同或前置 | 完成边界 |
| --- | --- | --- |
| T0 合同与探针 | 与 C1/C2 对齐 Build 索引、资源锁、运行时矩阵；与 C4 对齐主体/授权引用 | 两份设计不各建一套制品或授权协议 |
| T1–T5 本地资源能力 | 使用共同合同；可与云交付开发并行 | 本地验证通过不宣称云端可用 |
| T6 迁移和云准入 | T5 + C1/C2 + C3 DSH 路径 + C4；提供 C5 所需资源验收证据 | 首先在隔离云端 Agent 验证资源，再按 C5 处理选定旧部署 |
| T7 资源发布 | T5/T6；云端在范围内时 C5 对应组合通过 | 按实际生态、执行器和资源能力发布 |

基础交付团队负责 C1–C4 公共机制，资源团队负责 Worker、binding/scope 和业务适配，双方共同验收 C5。共享机制只实现一次；依赖未完成时允许本地范围单独验收，完整云端里程碑保持未完成。

## 进度与时间口径

C1–C5 当前未完成，不能承诺本轮即可发布。优先交付一个 Codex 插件的全新云端实例闭环，再扩展 DSH 和其他 harness 的矩阵。完成 C1/C2 并确认预发镜像、制品存储、Server 能力可用后，才有依据评估剩余联调时间。

资源设计的 27–40 人日、约 4–6 周是其声明人员配置下的资源能力规划，不能覆盖本文 C1–C5 全部公共工程。其 T6 的 3–5 人日仅包含公共云能力就绪后的资源迁移、适配和准入联调；制品平台、授权生命周期和 DSH 云恢复的建设成本需另行评估，不重复计算共有工作。

发版条件：云端交付和授权闭环通过上述验收，再运行仓库既有 preflight/公开候选 review。不能以本地技能可见、单测通过或仅增加部署阻断提示，替代云端验收。
