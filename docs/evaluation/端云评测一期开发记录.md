# 端云评测一期开发记录

## 定位

端云评测集的唯一数据底座是 EvalSmith。`agent-eval` 提供产品 API、项目和身份上下文适配；KsADK 默认经 AICP/KOP 调用它，不再要求用户配置或传入 agent-eval 服务地址。

一期主链路：

```text
本地 EvalSet
  -> KsADK 解析、固定六列转换、DataPolicy 预检
  -> agentengine evalset preview/push
  -> AICP KOP PublishEvaluationSetSnapshot（AK/SK 签名）
  -> agent-eval -> EvalSmith Dataset 创建或原子 publish
  -> DatasetId + DatasetVersion
  -> .agentkit/evaluation-bindings/<path-hash>.yaml
  -> CLI / Studio 固定版本 pull 和评测
  -> 本地 EvalRunReport 关联 Dataset version 与 TargetSnapshot
```

## 已实现

- KsADK 把 `EvalSetVersion` 转换为固定六列 Dataset Snapshot：`case_id`、`turns`、`assertions`、`case_metadata`、`source_format`、`ksadk_content_digest`。
- `agentengine evalset preview` 输出完整待发布快照；`push` 一期只更新已有 Dataset。
- 首次发布必须显式传 `--dataset-id`；随后按文件路径复用本地 `CloudBinding`；显式另一个 ID 会在发布成功后切换绑定。
- 默认使用 `full_trace`，自动生成幂等键，不发送 `BaseVersion`；只有远端返回的 content digest、schema hash、行数都与本地一致，才原子写入 Binding。
- `agent-eval` 提供 `PublishEvaluationSetSnapshot`：首次创建和已有 Dataset publish 都由 EvalSmith 在单一事务中创建不可变版本。
- `evalset pull` 通过 `DescribeEvaluationSet` 分页读取确定的 `DatasetId + DatasetVersion` 并恢复本地 EvalSet。
- 云 Dataset 固定版本可作为 CLI 和 Studio 评测输入，`EvalRunSpec/Report` 记录 Dataset ID、version、schema hash 和 content digest。
- Studio 评测表单不再提供 Dataset version 数字输入；用户从 Catalog 选择带 `vN` 标记的不可变快照，版本和摘要由选项自动带入请求。
- Studio Target 表单按类型显示业务控件：A2A 使用“Agent 地址”，Local Source 使用“Agent 源码目录”，Studio Build 使用 Build 下拉框；后端仍统一接收 `TargetRef.kind/locator`。
- 未设置 `AGENT_EVAL_BASE_URL` 时，KsADK 通过 AICP KOP 发送 `PublishEvaluationSetSnapshot`、`DescribeEvaluationSet`、`ListEvaluationSet`，复用 `KSYUN_ACCESS_KEY`、`KSYUN_SECRET_KEY`、`KSYUN_ACCOUNT_ID` 和既有预发路由信号。

### Catalog 选择语义与故障诊断

- Studio 的 `Dataset source` 选项对用户显示为 `Cloud Dataset`；Dataset version 不提供单独输入，版本仍由不可变快照选项自动带入。
- `ListEvaluationSet` 使用 `DatasetType=Manual` 获取产品评测集，再读取固定版本快照并校验 KsADK digest；不能使用 `Column=ksadk_content_digest` 代替类型筛选，否则会误命中 OnlineEval 或其他包含同名列的数据集，最终目录为空。
- Cloud Dataset 目录请求失败时，Studio 在字段下显示后端返回的错误；只有请求成功但没有符合不可变快照契约的数据时，才显示空列表。

## 使用

在包含 EvalSet 的工作区执行：

```powershell
# 本地预览，不访问云端
agentengine evalset preview --evalset-file evaluations/support.yaml --format json

# 首次绑定并更新已有云端评测集
agentengine evalset push `
  --file evaluations/support.yaml `
  --dataset-id <dataset-id> `
  --format json

# 后续更新：复用该文件的 Binding
agentengine evalset push --file evaluations/support.yaml --format json

# 显式切换到另一个已有 Dataset
agentengine evalset push --file evaluations/support.yaml --dataset-id <another-dataset-id>

# 拉取固定版本，不读取隐式 current
agentengine evalset pull `
  --dataset-id <dataset-id> `
  --dataset-version 3 `
  --output-file evaluations/imported-v3.yaml
```

`--file` 和 `--output-file` 必须位于当前工作区。Binding 按 EvalSet 相对路径保存，不是“最近一次命令”的全局状态。

正常云端使用需要 KsADK 已有的 KOP 全局配置：`KSYUN_ACCESS_KEY`、`KSYUN_SECRET_KEY`、`KSYUN_ACCOUNT_ID` 和适当的 `KSYUN_REGION`。不需要 Coze API Key、agent-eval 专用 API Key 或 `--agent-eval-url`。

`AGENT_EVAL_BASE_URL` 仅保留为显式 direct-HTTP 覆盖，用于本地开发、Mock 测试和私有部署。该模式可配合 `AGENT_EVAL_API_TOKEN`、`AGENT_EVAL_ACCOUNT_ID`，但不属于正式用户配置，且不会向该 URL 发送 KOP 签名。

## 测试用例与完整命令

可直接使用的 EvalSet 位于 `docs/evaluation/phase1-smoke-evalset.yaml`，包含确定文本、禁止错误文本和多轮记忆三个 Case。先在工作区根目录校验，不会执行 Agent 或访问云端：

```powershell
agentengine eval `
  --evalset-file docs/evaluation/phase1-smoke-evalset.yaml `
  --agent-dir . `
  --validate-only `
  --format json
```

自动化测试代码位于：

- `tests/test_cmd_evalset.py`：preview、首次 push、Binding 复用、固定版本 pull。
- `tests/test_cmd_eval.py`：本地/云端 EvalSet、CLI Target 选择、执行和报告输出。
- `tests/test_evaluation_agent_eval_client.py`：`ListEvaluationSet`、`DescribeEvaluationSet`、`PublishEvaluationSetSnapshot` 客户端合同。
- `tests/studio/test_evaluation_shell.py`：Studio Catalog、创建评测和报告查询 API。
- `ksadk/studio/react-ui/src/pages/EvaluationsPage.test.tsx`：Cloud Dataset 和 Target 业务控件。

运行结果默认保存到工作区 `.agentkit/evaluations/`，EvalSet 与云 Dataset 的 Binding 保存到 `.agentkit/evaluation-bindings/`。

### push 后直接评测固定云版本

首次需要在平台准备一个已有 Manual Dataset，并将 Dataset ID 传给 push。push 返回的 `datasetId` 和 `datasetVersion` 是后续评测必须固定使用的版本：

```powershell
$published = agentengine evalset push `
  --file docs/evaluation/phase1-smoke-evalset.yaml `
  --dataset-id <dataset-id> `
  --format json | ConvertFrom-Json

$published | Select-Object datasetId, datasetVersion, projectId, contentDigest
```

使用云 Dataset 评测本地源码 Agent：

```powershell
agentengine eval `
  --dataset-id $published.datasetId `
  --dataset-version $published.datasetVersion `
  --agent-dir D:\path\to\agent `
  --timeout-seconds 120 `
  --report-dir .agentkit/evaluations `
  --format pretty
```

如果返回了 `projectId` 且账号下存在多项目，使用完整项目参数：

```powershell
agentengine eval `
  --dataset-id $published.datasetId `
  --dataset-version $published.datasetVersion `
  --dataset-project-id $published.projectId `
  --agent-dir D:\path\to\agent `
  --format pretty
```

使用同一云 Dataset 评测远端 A2A Agent：

```powershell
agentengine eval `
  --dataset-id $published.datasetId `
  --dataset-version $published.datasetVersion `
  --a2a-url https://agent.example.com/.well-known/agent-card.json `
  --timeout-seconds 120 `
  --format pretty
```

需要鉴权时传凭据引用，而不是直接传密钥：

```powershell
agentengine eval `
  --dataset-id $published.datasetId `
  --dataset-version $published.datasetVersion `
  --a2a-url https://agent.example.com/.well-known/agent-card.json `
  --credential-ref <credential-reference> `
  --format pretty
```

也可以不经过云端，直接用本地 EvalSet 评测两类 Target：

```powershell
# Local Source
agentengine eval `
  --evalset-file docs/evaluation/phase1-smoke-evalset.yaml `
  --agent-dir D:\path\to\agent `
  --format pretty

# A2A
agentengine eval `
  --evalset-file docs/evaluation/phase1-smoke-evalset.yaml `
  --a2a-url https://agent.example.com/.well-known/agent-card.json `
  --format pretty
```

`agentengine eval` 当前没有 `--studio-build-id` 参数，不能通过 CLI 选择 Studio Build。Studio Build 评测需在 `http://127.0.0.1:8893/#/evaluations` 新建评测，选择 Local EvalSet 或 Cloud Dataset，再把 Target 类型设为 `Studio Build` 并选择具体 Build。CLI 增加 Studio Build Target 需要另行补充 Build 解析和 adapter 注入，不能用 `--agent-dir` 代替。

## 当前边界

- 已支持：预览、更新已有评测集、Binding 复用/切换、固定版本 pull、固定云版本参与 CLI/Studio 评测和本地 Report 追溯。
- 一期 CLI 不暴露创建 Dataset 入口；用户先在 Studio/平台准备已有 Dataset，再由 CLI 更新。
- 未支持：Studio 上传/Binding 管理 UI、云端 Experiment、Report/evidence 上传、Trace 候选回流、完整 RBAC/审计/留存闭环。
- EvalSmith 尚未持久化完整幂等结果；网络超时后 KsADK 不能自动安全重试。
- EvalSmith 尚无条件 publish，故 KsADK 不暴露也不发送 `BaseVersion`，不以客户端先读后写伪造并发安全。
- EvalSet 顶层 `metadata` 尚未完整进入 EvalSmith Dataset 主模型。
- 上线前必须在 KOP 预发和线上登记 `PublishEvaluationSetSnapshot`；在 Action 未登记时，KOP 会明确返回 `InvalidActionOrVesion`，客户端不会静默回退到直连。
