# 端云评测一期开发记录

## 定位

端云评测集的唯一数据底座是 EvalSmith。`agent-eval` 仅提供账号、项目、鉴权和产品 API 适配，不再将 Coze 作为此链路的依赖或目标。

一期打通的链路如下：

```text
本地 EvalSet
  -> KsADK 解析、固定六列转换、DataPolicy 预检
  -> agentengine evalset preview/push
  -> agent-eval POST /PublishEvaluationSetSnapshot
  -> EvalSmith Dataset 创建或原子 publish
  -> DatasetId + DatasetVersion
  -> .agentkit/evaluation-bindings/<path-hash>.yaml
```

## 已实现

- KsADK 将 `EvalSetVersion` 转换为固定六列 Dataset Snapshot：`case_id`、`turns`、`assertions`、`case_metadata`、`source_format`、`ksadk_content_digest`。其中 `turns` 和 `assertions` 是对象数组，`case_metadata` 是允许扩展字段的对象。
- `agentengine evalset preview` 输出即将发送的完整快照。
- `agentengine evalset push` 对标 VEADK，一期用户入口只更新已有 Dataset：某个 EvalSet 文件第一次发布必须显式传 `--dataset-id`，之后可以省略并复用该文件的本地 `CloudBinding`；显式传另一个 ID 会在发布成功后切换绑定。
- CLI 默认使用 `full_trace`，自动生成幂等键，不发送 `BaseVersion`；远端成功且内容摘要、规范摘要、行数一致后，才原子写入本地 `CloudBinding`。
- `agent-eval` 新增 `POST /agentengine/eval/api/v1/PublishEvaluationSetSnapshot`：首次发布调用 EvalSmith `POST /api/v1/datasets`，后续发布调用 `POST /api/v1/datasets/:id/publish`，两种操作都由 EvalSmith 在单一事务中创建不可变版本。
- 上传请求携带 `ContentDigest`、KsADK 规范 `SchemaHash` 与 `IdempotencyKey`；后两个 Hash 的计算方式和 EvalSmith 内部字段 Hash 不同，返回给 KsADK 的是其规范 Hash，避免跨系统算法差异破坏绑定。
- `evalset pull` 复用 agent-eval 已有的 `DescribeEvaluationSet`，显式传 `DatasetId + DatasetVersion`，逐页读取固定版本并恢复本地 EvalSet。
- `AGENT_EVAL_BASE_URL`、`AGENT_EVAL_API_TOKEN`、`AGENT_EVAL_ACCOUNT_ID` 已进入 KsADK 全局配置组。未单独配置 `AGENT_EVAL_ACCOUNT_ID` 时，客户端自动回退到已有的 `KSYUN_ACCOUNT_ID`。

## 使用

在包含 EvalSet 的工作区执行：

```powershell
agentengine evalset preview --evalset-file evaluations/support.yaml --format json

# 第一次：绑定并更新已有云端评测集
agentengine evalset push `
  --file evaluations/support.yaml `
  --dataset-id <dataset-id> `
  --agent-eval-url https://<agent-eval-host> `
  --format json

# 后续：该文件已存在 Binding，可省略 dataset-id
agentengine evalset push `
  --file evaluations/support.yaml `
  --agent-eval-url https://<agent-eval-host> `
  --format json

# 显式指定另一个 ID，会在成功后把该文件切换到新 Dataset
agentengine evalset push `
  --file evaluations/support.yaml `
  --dataset-id <another-dataset-id> `
  --agent-eval-url https://<agent-eval-host>

# 拉取一个固定云端版本，不读取隐式 current
agentengine evalset pull `
  --dataset-id <dataset-id> `
  --dataset-version 3 `
  --agent-eval-url https://<agent-eval-host> `
  --output-file evaluations/imported-v3.yaml
```

`--file` 和 `--output-file` 必须位于当前工作区。Binding 是按 EvalSet 相对路径保存的，不是“自动记住最近一次命令”。Token 仅从环境变量或全局配置读取，不会写入 Binding 或报告文件。

预发联调已验证不需要单独传 Coze API Key 或 Bearer Token，但必须有租户账号上下文。正常使用已有 KsADK 全局 `KSYUN_ACCOUNT_ID` 即可；若经过需要 Bearer 鉴权的网关，再配置 `AGENT_EVAL_API_TOKEN`，无需增加 Coze 专用参数。

## 当前边界

- 已支持：预览、更新已有评测集、Binding 复用/切换、固定版本 pull，以及云端 Dataset 固定版本作为本地评测输入并写入 `EvalRunSpec/Report`。
- agent-eval 底层保留创建完整 Dataset snapshot 的能力，但一期 CLI 不暴露创建入口；用户先在 Studio/平台准备已有 Dataset，再由 CLI 更新。
- 未支持：Studio 上传 UI、云端 Experiment 创建、Report/evidence 上传、Trace 候选回流，以及完整的 RBAC/审计/留存闭环。
- `Idempotency-Key` 已由 KsADK 透传到 agent-eval 和 EvalSmith 请求头；EvalSmith 尚未保存幂等请求结果，因此网络超时后的自动重试尚未启用。
- agent-eval schema 仍兼容 `BaseVersion` 字段，但当前 EvalSmith 没有条件发布接口；KsADK CLI 不暴露也不发送该字段，不能在客户端先读版本再写来伪造并发安全。
- EvalSet 顶层 `metadata` 尚未进入 EvalSmith Dataset 主模型；一期固定六列可完整恢复 Case、turns、assertions 和 Case metadata，但顶层 metadata 的云端保真仍需补合同。
