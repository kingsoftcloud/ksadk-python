# 人机交互(Human-in-the-Loop)跨框架接入指南

本文档面向用 `ksadk-python` 开发 Agent 的业务开发者。**核心承诺:你只按框架官方文档写 agent 的审批/中断代码,ksadk 自动把它桥成卡片式交互 UI(审批/多选/表单),并处理暂停、恢复、事件持久化与回放。你不需要学任何 ksadk 专属的人机交互 API。**

覆盖框架:LangGraph / LangChain / DeepAgents / Google ADK / Codex。

---

## 1. 统一模型:框架原生 interrupt → ksadk 自动桥接

无论哪个框架,人机交互的底层都是同一件事:**框架在某个点暂停执行、把一个 JSON-serializable 的"请求"抛出来、等外部回包后恢复**。ksadk 在运行时层做三件事,对业务代码透明:

1. **捕获**框架原生 interrupt/approval 信号,翻译成统一的 `approval.requested` 事件(进 `RuntimeEventStore`,可订阅/回放)。
2. **渲染**成 A2UI 卡片(审批卡 `ApprovalBar` / 多选 `Select` / 表单 `Form`),经 SSE 推到 hosted/local UI。
3. **恢复**:用户在卡片上的操作回传成 `a2ui.action`,由平台协议层翻译回框架原生的 resume 调用(`Command(resume=...)` / ADK confirmation / Codex `steer`)。

```
你的 agent(框架原生写法)          ksadk 运行时(自动,你不写)
  interrupt(payload)        ──►  approval.requested 事件
                                  + A2UI 卡片(ApprovalBar/Select/Form)
                                  └─► SSE ─► UI 渲染
                                         人操作 ─► a2ui.action 回传
                                         ──► 框架原生 resume(Command/confirm/steer)
```

**关键:你的业务代码只负责"在哪里暂停、暂停时抛什么、恢复后怎么用"——和框架官方文档一字不差。** 不引入 ksadk 专属装饰器、基类或事件类型。

## 2. 各框架接入写法

### 2.1 LangGraph

按 [LangGraph interrupts 官方文档](https://docs.langchain.com/oss/python/langgraph/interrupts) 写。在节点里调 `interrupt()`,用 `Command(resume=...)` 恢复。

```python
from langgraph.types import interrupt, Command

def approval_node(state):
    decision = interrupt({
        "question": "是否执行该操作?",
        "details": state["action_details"],
    })
    # resume 的回包 = interrupt() 的返回值
    if decision:
        return Command(goto="proceed")
    return Command(goto="cancel")
```

- 必须配 checkpointer(生产用 `AsyncPostgresSaver`,本地调试用 `InMemorySaver`)。
- `thread_id` 由平台注入(= session 级),你不用管。
- ksadk 自动:把 interrupt payload 桥成审批卡;用户点批准/拒绝后,平台调 `graph.stream_events(Command(resume=<decision>), config=...)`。

### 2.2 LangChain

按 [LangChain HITL 官方文档](https://docs.langchain.com/oss/python/langchain/human-in-the-loop) 写。用 `create_agent` + `HumanInTheLoopMiddleware`。

```python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model=...,
    tools=[write_file, execute_sql],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "write_file": True,  # 允许 approve/edit/reject/respond
                "execute_sql": {"allowed_decisions": ["approve", "reject"]},
            },
        ),
    ],
    checkpointer=InMemorySaver(),  # 生产用 AsyncPostgresSaver
)
```

- LangChain `create_agent` 返回的就是 LangGraph `CompiledStateGraph`,所以底层走 LangGraph interrupt。四种决定类型(approve/edit/reject/respond)都支持。
- ksadk 自动:工具调用触发审批时,桥成审批卡;用户决定回传成 `Command(resume={"decisions":[...]})`。

### 2.3 DeepAgents

DeepAgents 的 `create_deep_agent` 同样返回 LangGraph 图,写法与 LangGraph 一致。详见 `docs/frameworks/DeepAgents说明.md`。

### 2.4 Google ADK

ADK 工具支持 `check_require_confirmation` 原生确认机制。在工具定义里声明需确认,ksadk 运行时捕获并桥成审批卡。

```python
# ADK 工具声明需确认(按 google-adk 官方写法)
# 工具被调用时,ADK 暴露 requested_tool_confirmations
# ksadk 自动:桥成 approval.requested 事件 + 审批卡
# 用户批准后,平台经 invocation_id resume(ADK forward-only)
```

> ⚠️ **当前状态(2026-07-23)**:ADK 原生确认机制(`BaseTool.check_require_confirmation`)存在,但 `ADKRunner` **尚未 surface 审批事件**——这是已知缺口,见第 4 节。在补齐前,ADK agent 的审批暂走 paradigm 1 工具网关(见第 3 节)。

### 2.5 Codex

Codex 通过 `approval_mode` + guardian approval review,turn 执行到需审批项时发 `item/approvalRequest` notification。ksadk 运行时已 surface 此通知为 `approval.requested` 事件。

```python
# Codex agent 创建时配 approval_mode(按 openai-codex 官方写法)
# handle.turn(input, approval_mode=...) → turn 挂起等审批
# ksadk 自动:item/approvalRequest → 审批卡;用户决定 → handle.steer / thread_resume
```

- ksadk 已实现:`pending_approvals` 跟踪、`handle.interrupt` 真中断、cancel 时级联丢弃 pending 审批(见 `ksadk/codex/runtime.py`)。

## 3. 补充:工具网关审批(paradigm 1,框架无关)

除框架原生 interrupt,ksadk 还提供**工具网关**——在工具执行前按风险等级(strict 模式门 `medium/high/critical`,如 `run_command`/`run_code` 正是 high)强制审批。这是 Claude Code 式的权限模型,**对任何框架生效**(因为工具经网关执行)。

- 适合:框架没有原生 interrupt,或你想统一给所有工具加一层风险门。
- 区别:网关审批返回 `approval_required` 给 agent;对 LangGraph 这只是普通工具结果(不会真暂停图),所以 LangGraph agent 仍建议用第 2.1 节原生 interrupt。

## 5. 你只需要记住的三件事

1. **按框架官方文档写 interrupt/审批**,不学 ksadk 专属 API。
2. **配 checkpointer**(LangGraph 系;生产用 PG),否则不能跨进程恢复。
3. **暂停语义归框架,resume 语义归平台**:你定义"暂停抛什么",平台负责"用户操作后怎么调 resume"。
