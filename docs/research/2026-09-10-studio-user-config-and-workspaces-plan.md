# Studio 全局配置、工作区切换与目录关联：设计、一期验收与交接规格

日期：2026-09-10。状态：已完成整体设计复核，并按用户要求确定一期同时交付全局配置、工作区切换和目录关联；未实施、未提交、未发布。配置服务、Runtime 适配和进程模型验证属于一期内部步骤，不是推迟三项功能的独立产品阶段。本轮核对源码、测试定义和文档一致性，没有执行 DSH、模型调用、跨工作区运行实验或性能测试。KsADK 核验基线为 `852d4382f2db9d8138cc63b333cf5d36a28873f1`；DSH 源码基线及逐项证据见 [DSH 工作区研究](2026-09-10-dsh-workspace-evidence.md)。

## 1. 建议决策

**一期同时交付三项能力：全局配置、工作区切换、目录关联。** 用户在一个 Studio 入口配置常用连接、打开多个工程，并让当前任务按授权访问其他目录；不迁移正在运行的会话归属。三项能力共同形成一期验收，不以只完成配置服务代替一期完成。

产品目标是：用户配置一次常用连接，在不同 Agent 工程之间打开、开发、验证和返回；已有任务仍在原工程内完成。能力名称建议为“打开/切换工作区”，不要宣传为“Agent 动态迁移工作空间”。

当前工程中的 Agent 可以关联、读取和按授权修改其他工程或普通目录，无需切换所属工作区。这里“任务仍在原工程”表示任务、历史和配置来源保持归属，绝不表示文件访问只能发生在该工程之内。关联目录在实现上独立于工作区列表，但两者在一期一起交付；即使用户只打开一个工作区，也可以使用关联目录与已支持的本地完全访问模式。

已确认的需求是配置复用、同入口切换工程及跨目录工作。尚无多用户使用频率、并发工作区数量和跨目录任务接力的测量数据；这些数据用于优化一期体验和决定后续扩展，不再作为三项一期功能是否立项的前提。运行中迁移会话、多账号管理中心、全局 Agent 库和云多租户治理不纳入一期。

### 1.1 一期目标与完成口径

本文件可直接作为研发和测试交接输入：第 1 节确定目标，第 4–7 节约束设计，第 8.3–8.7 节是验收规格，第 10 节列交付物与职责。所有验收用例当前状态均为 `NOT_RUN`；文档完整不代表功能已实现。

| 目标 | 一期必须达到的结果 | 主要验收编号 |
|---|---|---|
| G1 配置一次，多工程复用 | 一次保存用户默认模型/云连接，A、B 均可使用；项目可覆盖和恢复继承；无需重复填密钥或手动编辑配置文件 | CFG-01、CFG-02、CFG-03、E2E-01 |
| G2 一个入口切换工程 | 一次启动 Studio，打开/新建/切换 A、B；至少两个工作区各有一个任务同时进行；切换不终止原任务，可返回查看、审批或取消 | WS-01、WS-02、WS-03、E2E-01 |
| G3 当前任务可跨目录工作 | A 中的 Agent 可读取 B 和普通资料目录；按授权可写 B；支持本地完全访问选择，无需迁移会话或初始化被关联目录 | DIR-01、DIR-02、DIR-03、DIR-04 |
| G4 用户能理解当前状态 | 页面能看清当前工作区、配置来源、有效目录权限、后台任务及保存/权限的生效状态；已授权操作不逐文件重复确认 | CFG-03、CFG-07、DIR-05、DIR-06、UX-01 |
| G5 运行归属正确、可追溯 | 请求、会话、Trace、审批和文件引用归属正确；显式跨目录操作记录真实文件目标，配置变更不偷偷换账号或计划目标 | CFG-08、WS-04、WS-05、DIR-07、E2E-02 |
| G6 安装版可交付 | 从候选 wheel 干净安装后完整流程通过；旧环境升级配置不丢；静态资源与候选源码一致，不依赖源码目录或手工复制文件 | PKG-01、PKG-02、PKG-03、PKG-04 |

**一期完成 = G1–G6 同时满足 + 必测矩阵用例全部通过 + 交付证据完整。** 只合入配置服务、只做出目录下拉框、只在 editable 安装中通过，均不能标记一期完成。二、三期内容是路线图，不能用来延期一期的三个核心功能。

## 2. 需求为什么成立，什么情况下不成立

| 使用情境 | 用户真正需要的能力 | 判断 |
|---|---|---|
| 新项目重复填写模型、AK/SK、控制面地址 | 用户默认连接与项目覆盖 | 现在做，直接对应本次反馈 |
| 在两个 Agent 工程间切换开发、测试、看历史 | 最近工作区、打开目录、返回原项目 | 一期交付；不要求原会话改目录 |
| 同一工程里有多个 Agent | Agent 列表、会话分组 | 已有项目组织就能承载，不需人为拆目录 |
| A 工程的 Agent 参考 B 的源码、资料或联动修改 B | 关联任意目录，允许读取并按需赋予写权限 | 纳入轻量设计；不需要先把 B 初始化成 Studio 工作区 |
| 一个 Agent 分析两个文档集合 | 选择输入文件/资料集合，必要时显式增加文件权限 | 先做数据选择，不把资料分类强制升级为工作区 |
| 同一套 Agent 能力用于多个项目 | 导入模板或复用固定 Agent 版本，目标环境重新绑定 | 单独需求；不等同于项目切换 |
| 同时跑 A 的评测、编辑 B 的 Agent | 后台任务保留、工作区标识和基础资源限额 | 一期保证基本流程；完整任务中心在二期扩展 |
| Agent 执行到一半从 A 移到 B | 执行状态迁移、外部副作用交接、权限再准入 | 本期不做；摘要交接新会话通常更清楚 |
| 企业不同客户/租户的数据隔离 | 身份、授权、独立沙箱及服务端存储隔离 | 属于平台能力，目录切换不能承诺这一点 |

Studio 的已有定位是 Agent 工程的本地开发、构建、验证和部署入口，见 [一期产品基线](../agentkit-local-studio-phase1-delivery-design.md)。工作区应服务这一定位；对无文件操作的问答、知识库或业务工具 Agent，不应要求用户理解更多目录、进程或配置文件。

一期候选完成后用 3–5 位现有开发者试用完整两项目流程，记录是否能配置一次、切换工程、关联资料并返回后台任务，观察操作成本和理解偏差。人数只是建议的发现性样本，不代表统计结论。试用结果用于修正一期体验，并判断是否值得建设二期统一任务中心和多账号管理能力。

## 3. DeepSeek Harness 给出的启发与限制

DSH 采用用户级设置和凭据服务、目录注册、会话按工作目录归组。核心区别是：工作区选择影响新会话；已存在会话的 cwd 是其持久事实。它没有把“切换项目”等同于“替换当前 Agent 所有执行状态”，也没有把每个工作区进程作为通用实现前提。

| DSH 的具体选择 | KsADK 应如何取舍 |
|---|---|
| `~/.dsh` 统一承载用户设置、凭据与状态，内部使用不同文件 | 复用已有 `~/.agentengine`，让用户通过统一设置入口管理；无需强求所有内部数据写入同一文件 |
| 启动环境固定；切换工作区不会重新读取目标目录 `.env` | KsADK 若承诺项目配置生效，必须按目标工程显式解析，不能直接照搬这一行为 |
| Session 固定 cwd，fork 也保留原目录 | 项目切换选择或创建目标会话；跨项目接力另建会话并明确交接内容 |
| 默认同一个 Host 管理多个 Agent，执行侧另有沙箱策略 | 先定义归属与权限，再评估同进程或 Worker；目录注册不等于隔离 |

DSH 的详细源码、测试断言、全局目录和配置优先级列在 [证据附录](2026-09-10-dsh-workspace-evidence.md)。该研究是固定源码分析，不代表本轮已经完成 DSH 产品运行验收。DSH 官方仍标注为开发者预览，参考的是设计选择，不应因此承诺上游全部行为稳定。[官方项目说明](https://github.com/deepseek-ai/deepseek-harness)

对 KsADK 的取舍：借鉴“用户默认可复用、选择目录创建会话、会话保留原目录”；配置优先级按 KsADK 现有兼容要求制定。工作区列表本身不代表安全隔离；DSH 的配置和权限规则不能直接当作 KsADK 跨账号隔离的证明。

## 4. 必须先统一的产品概念

| 概念 | 含义和边界 |
|---|---|
| 用户配置 | 当前操作系统用户的默认模型、连接和偏好；不是所有租户共享的服务端配置 |
| Studio 工作区 | Agent 工程目录，包含声明、构建记录和本地状态；内部有稳定 workspaceId |
| Agent 定义/版本 | 行为、能力和依赖的声明及固定制品；当前归属工作区，第一版不强行全局化 |
| 默认执行目录（cwd） | 相对路径解析和命令启动的默认位置，可与工程目录不同；不是可访问文件的完整范围 |
| 文件访问策略 | 独立确定可读、可写目录或本地完全访问；可以覆盖多个工程和普通目录 |
| Session | 固定所属工作区、Agent 及来源关系；访问外部目录不需要换会话，迁移归属才另建关联会话 |
| Run | 启动时确定 Agent/Build、默认执行目录、配置版本及初始授权；页面切换不改变这些关系，用户显式扩展目录权限可形成后续授权版本 |

这一划分尤其适用于当前 KsADK：Codex 的 cwd 使用工作区根目录，而 Harness 内置工具可使用持久状态目录下的工具工作区，且禁止写入不可变 Bundle。不能用一个新的 UI 下拉框，把所有 Runtime 的执行目录一律改成 Studio 项目目录。[Codex 解析器](../../ksadk/studio/codex_run.py#L91)、[Harness 工具目录](../../ksadk/plugins/providers/harness_managed.py#L65)

## 5. 用户级配置方案（一期）

### 5.1 存储和读取

复用 `~/.agentengine/settings.json` 保存用户默认，复用项目 `.agentkit/config.yaml` 保存项目覆盖。模型、云账号采用完整“连接”选择，项目仅记录选择与确有需要的覆盖，不复制全局秘密值。不新增需要用户管理的 `.ksadk` 目录；已有会话数据库和缓存是内部运行数据，本期不做大规模目录搬迁。

一期支持每类连接的一组用户默认及项目完整覆盖，沿用现有 connection_ref 绑定，内部记录版本；命名多账号库、账号管理中心与复杂连接路由留待后续需求，不作为配置复用的前置条件。迁移保留全局文件中的已有分组、身份缓存和未知兼容字段，避免重建文件时丢弃未涉及的数据。

全局目录已经存在，但 CLI 目前将其作为环境变量回退，Studio 解析器无法保留完整全局来源；`config set --global` 还会先写项目 `.env` / YAML，再写全局。全局保存也尚未采用工作区配置的原子写入与显式 0600 权限。这些是本期需要补齐的现状，而非已经解决。[全局读取与保存](../../ksadk/configs/global_config.py#L57)、[CLI 加载](../../ksadk/cli/__init__.py#L463)、[CLI 写入](../../ksadk/cli/cmd_config.py#L179)

将配置解析下沉到 `ksadk/configs` 的公共服务，由 CLI、Studio 和 Runtime 构建器调用。读取返回有效值、来源、作用域、配置版本；展示接口只返回脱敏状态。不能先把工作区 A 配置塞进全局 `os.environ`，再让 B 把它当作启动环境继承。

普通配置的优先级保留现有工作区保存语义，自高到低为：本次命令/请求的显式参数 > 显式 `--env-file` > 工作区保存配置 > 干净的启动环境快照 > 目标项目 `.env` > 用户默认 > 内置默认。显式参数仅在所属命令/请求及目标工作区内生效；启动 A 时传入的 `--env-file` 只绑定 A，不随 Host 自动传给 B。Host 的干净环境指加载任何项目 `.env`、全局回退和配置桥接之前的继承环境，而非从已污染环境中猜测删除字段。目标 `.env` 只解析目标工程，不向上搜索到其他项目；记录内容版本并在后续 Run 准入时检查变更。

全局是默认层；“先读取全局”不等于它可以压过项目选择。兼容处理 `OPENAI_BASE_URL` / `OPENAI_API_BASE`、`KSYUN_REGION` / `AGENTENGINE_REGION` 等别名，避免两个名字来自不同层导致行为分叉。权限授权另按 6.1 节处理，不套用“项目文件优先就能扩大权限”的规则。

云连接先选择来源或 connection_ref，再解析其中的 AK/SK 凭据对及控制面、身份；半套覆盖不能静默拼接另一来源的凭据。区域、桶和模型名等普通选项可对同一连接显式覆盖，端点/账号改变要重验绑定，并以完整解析结果记录来源与版本。模型连接同理处理端点和密钥。保留已验证的既有连接；仅修改同一账号的区域不应被误判为必须重填全部凭据。

### 5.2 页面与生命周期

设置页显式显示“用户默认 / 当前工作区”，默认展示当前工作区的有效值与继承来源；保存目标明确，不因自动猜测而扩大影响。常用连接可选择“保存为用户默认”；提供“恢复继承”和“仅用于此工作区”。清空输入、删除覆盖、删除共享连接是不同操作，尤其不能把密钥留空当作删除。

修改用户默认影响继承者后续创建的运行，项目覆盖者不受影响；已有会话、排队请求与定时任务按下表处理。保存的配置版本与工作区正在使用的版本分别展示。一期允许保存待生效配置：已有运行、审批等待和已接收请求使用其已绑定版本；需要刷新而无法并存两代客户端的工作区停止接收依赖新版本的运行，待旧活动归零后切换。其他工作区正常运行，不能要求整个 Host 同时空闲。暂未实现该机制的入口保留明确的忙碌响应，不能声称已热更新。[当前设置生效限制](../../ksadk/studio/service.py#L3272)

| 变化或操作 | 生效规则 |
|---|---|
| 修改温度、模型等普通配置，或同一连接轮换密钥 | 后续 Run 解析新版本；身份未变且重新准入通过时可继续原会话 |
| 更换云账号、控制面或资源归属 | 旧 Session 和资源记忆保留原身份；不自动拿新身份恢复旧 checkpoint。用户切换身份后创建新会话，历史仍可按其原本访问规则查看 |
| 请求排队、等待审批、崩溃恢复 | 接收时绑定工作区、Agent/Build、配置/连接与授权版本；执行/恢复时校验仍有效，不读可变的“当前账号”。旧绑定不可用则明确失败或要求重新提交 |
| 定时任务触发 | 固定目标工程、版本和授权引用；可在同一身份下获取轮换后的密钥，不能随全局默认更换账号、目录或 Build。需要换目标时显式更新计划 |

这些规则应沿用现有资源身份及计划目标契约，不另造仅靠工作区 ID 表示账号的身份体系。[InvocationIdentity](../../ksadk/resource_runtime/contracts.py#L106)、[计划目标](../../ksadk/scheduler/contracts.py#L83)。无需平台身份的纯本地会话不应被强制绑定云账号；是否能更换模型并恢复由相应 Runtime 适配器声明。

持久运行记录保存来源和连接版本，不将明文密钥写入会话、事件或 Bundle。凭据撤销和账号安全处置按权限策略执行，不能承诺“旧 Run 固定版本所以撤销后仍可继续”。展示已注册工作区中可确定的影响范围，不能声称已枚举磁盘上全部项目；旧连接仍被会话引用时保留可诊断状态。

写入使用指定作用域、版本检查、跨进程互斥、原子替换和限制权限，保护 CLI 与多个 Studio 的并发保存。保存成功指文件已落盘，不等于所有 Runtime 已切换；每个工作区在准入时核对版本，文件监听只用于加速。损坏文件报错；不把可恢复读错当成空配置后覆盖。

### 5.3 迁移原则

旧工作区配置继续兼容；不自动把项目秘密提升为全局。提供一次性“保存此连接为用户默认”，用户决定是否同时移除本项目的重复覆盖。纳入管理的用户运行设置统一写入服务；`--global` 只改全局，项目设置命令只改项目，配置查看与实际启动共用解析器。全局 schema 补齐控制面地址等被 CLI 与 Studio 共用的字段。记录双写行为修正，依赖旧行为的脚本改为显式分别保存两个作用域。

收敛的是运行设置与凭据，`agentengine.yaml` / `agentkit.yaml` 等工程、构建和部署声明保持原有职责。当前 `config set` 还接受任意工程字段及环境变量，不能把所有 YAML 和 `.env` 写入一律搬到 `.agentkit/config.yaml`；先建立受管理设置、工程声明、普通应用环境变量的字段归属表，再按原有命令兼容路由。未知字段不静默丢弃；全局不适用的工程字段在写入前明确报错，避免一半写入成功。交互配置向导与非交互命令采用相同规则。[现有 CLI 字段分类](../../ksadk/cli/cmd_config.py#L154)

实现上配置服务不依赖多进程管理，可以先完成并验证；一期最终还要在同一 Studio 入口完成工程切换和目录关联验收。

## 6. 多工作区的最小产品（一期）

入口只有“最近工作区 / 打开已有目录 / 新建工作区”。打开目录时展示路径、初始化意图与已选择连接。移除最近记录只隐藏记录，不能删除工程目录、会话、产物或停止后台任务；重新打开同一规范路径复用本机注册身份。内部 workspaceId 由本机注册表分配，不从复制来的工程配置直接继承，规范路径用于去重；路径大小写按实际文件系统判断。

一期中移动目录后原记录标为不可用，支持按新路径打开，但不承诺将已有原生会话原地恢复到新路径。保留旧记录和运行路径；只在 Runtime 证明可恢复且没有活动任务时，后续再提供保留身份的重新定位。不能把修改注册表路径当作完成 checkpoint 迁移。

工作区切换是当前浏览器标签页的选择。服务端不维护一个会被所有标签页共同改写的 `activeWorkspace`。所有请求、事件订阅、附件引用和缓存键携带工作区作用域；旧请求响应不能覆盖新工作区页面。URL 能恢复所在工作区与会话，浏览器返回不会将新工作区 ID 配上旧会话。

建议服务面为 `WorkspaceRegistry + WorkspaceRuntimeManager`；注册表只存最近目录、标识和展示元数据，不保存额外凭据。路由使用工作区 ID 查找已注册、用户授权的路径，不能把任意客户端传入路径直接变成文件读取根目录。继续保留 loopback、认证和 CSRF 保护。

现有 `/api/v1/workspaces:open` 只接受启动 root，路由闭包也绑定单个 StudioService。[现有入口](../../ksadk/studio/api.py#L1040)、[Service 绑定](../../ksadk/studio/service.py#L199)。首版要有明确的兼容层：旧路径仍绑定启动工作区，新路径按 workspaceId 路由；资源声明、构建、设置、会话、文件、SSE 和共享会话 UI 一起核对，不能只改列表 API。

选择 B 后，A 中正在执行、等待审批、评测、构建或部署的操作继续归属 A。一期必须提供最小后台状态入口，至少显示 A 仍在执行/等待审批，可回到 A、处理原任务或取消；容量治理与统一任务中心再放二期。新会话在 B 创建；A 的历史、文件引用、记忆、审批和原生 checkpoint 不迁到 B。第一版在 B 使用 B 已有 Agent；模板/固定版本导入仅复用已有能力，不将新建导入平台作为前置条件。跨工程资源 ID、插件、凭证和本地相对路径需要重新解析，不能承诺任意 Build 无条件可复制。

一期同时需要基本的异常退出检测和可见失败状态，保留日志与历史，不自动重放可能已有外部副作用的任务。二期增强自动恢复和调度治理，不能把一期的失败可见性及基础资源上限一起推迟。

“在其他工作区继续”如有实需，后续创建关联会话并传用户选定的摘要与产物引用；明确不拷贝秘密、旧权限、可变运行句柄或原生 checkpoint。

### 6.1 关联目录与文件访问（一期）

**一个任务可以有一个所属工作区和多个可访问目录。** 例如任务属于 A，默认 cwd 为 A；Agent 同时读取 B 的代码和一份下载目录的文档，并在获得写权限后修改 B。会话、Trace 和任务列表仍归属 A，文件变更展示实际目标路径。这是跨目录协作，不是迁移运行状态。命令也可显式以 B 为本次 cwd 执行，不调用 Host 的全局 `os.chdir`，不改会话的默认目录和身份。

关联目录不要求是 Git 仓库、KsADK 工程或已注册工作区；不初始化 `.agentkit`，不复制文件，不启动另一个 Studio。关联 B 不自动加载 B 的 `.env`、云账号、插件启动脚本或 Agent，也不合并 B 的会话历史。若用户选择了广泛读取或完全访问，B 的配置文件可能作为普通文件可读；“不自动继承配置”不能被宣称为文件保密隔离。

建议提供以下本地模式，首次明确选择后记住用户偏好；用户可在项目或会话中明确覆盖。已有用户的模式保持兼容，不因升级静默扩权。每个 Runtime 仅展示已验证支持的模式。

| 模式 | 读取 | 写入 | 适用场景 |
|---|---|---|---|
| 本地开发（建议默认） | 当前 OS 用户及有效执行策略允许的本机文件，不额外按 Studio 工作区截断 | 主执行目录及用户选择的可写关联目录，保留制品完整性规则 | 跨仓阅读、查资料、日常开发 |
| 指定目录 | 主目录和显式关联的可读目录 | 主目录和显式关联的可写目录 | 用户希望限制任务可见范围 |
| 本地完全访问 | 当前进程在 OS 权限下可访问的文件 | 同一 OS 权限范围内的文件 | 用户信任的自动化；不逐目录申请，也不宣称租户或 Bundle 文件不可被外部命令改动 |

文件权限、网络权限和工具审批是不同维度；可以用简单预设联动，但不能把“允许读 B”解释为允许任何命令或更换账号。完全访问也不产生管理员身份，不绕过操作系统隐私权限；远程 Runtime 只覆盖其所在主机或沙箱，不会自动看见用户电脑，需要另行挂载或传文件。

权限扩大只能来自用户在已认证设置界面、CLI 或当前任务中的明确授权。项目文件、Agent 声明、工具结果和模型生成的“已获授权”只能表达请求，不能自行扩大权限；已有授权范围内的操作继续自动执行。关联目录配置保存用户的选择，受限模式下 Host 还要核对控制层的授权记录与策略版本，不能仅靠 Agent 可改写的项目 YAML 判断是否已授权。完全访问模式保留同一 OS 用户的信任边界，不额外承诺能对抗有权修改 Host 数据的本机进程。

界面提供“关联目录”，通过选择器、粘贴路径或明确的自然语言指令添加，显示名称、路径和可读/可写状态。默认新关联用于参考读取，用户说“同时修改 B”即可将明确目标作为写入授权；现有授权覆盖的操作不再逐文件询问。广泛读取模式下，关联的额外价值是告诉 Agent 优先搜索哪里、在文件树展示并记住关系；它不是读取外部文件的必经门槛。允许为当前会话临时添加，或记住为本工程关联目录；通过现有配置服务保存，绝对路径不写入可发布 Bundle，不另增用户维护文件。

页面显示的是有效权限：若 B 已被可写的父目录覆盖或处于完全访问模式，给 B 增加一个“参考读取”关联不会使它变成只读。移除关联默认只移除导航/搜索关系，并撤去该关联单独授予的权限；其他授权仍可生效，界面需直接说明。用户要求禁止再访问 B 时，需要调整实际策略；若当前广泛读取/完全访问后端不支持目录例外，则切换到可表达限制的模式，不能用删除一条列表记录伪造撤销。

运行中新增关联目录不改变 owner workspace 或账号。访问策略记录版本；支持热更新的 Runtime 在下一次工具调用前生效，不支持的在当前执行结束后为下一轮应用。文件关联列表可立即更新，权限状态必须分别显示“已生效/待生效”。需要重建沙箱但无法无损保留当前运行状态时，保留历史并明确仅在下一轮或新运行生效，不承诺透明热切换。

撤销应阻止后续工具访问，但不能收回已读入上下文的内容；已启动的命令及其后代进程可能继续访问，用户要求立即停止时需停止相关进程树后才能报告完成撤销。旧审批还要校验原任务、实际路径、操作与当前授权版本，不得在路径或权限变化后直接复用。不能靠放宽全部权限模拟一个只读关联。

工程实现中，将 `owner_workspace_id`、默认 `cwd`、关联目录和有效访问策略分别建模，并传入文件读取、搜索、编辑、shell 及子 Agent。子 Agent 默认继承或收窄父任务权限。关联路径做规范化，路径别名和符号链接按有效策略解析；文件事件带任务归属与实际目标，跨目录同名文件不能混淆。结构化编辑使用文件版本检查；对普通 shell、外部编辑器和完全访问脚本，不承诺统一拦截写冲突，提供实际变更结果并提示已检测到的并发修改。

现状还没有统一实现：Studio 的工程文件接口和 Harness 的部分文件/只读执行工具仍校验单 root；Codex 路径已有权限预设，但不能由此推定所有 Runtime 都支持关联目录。[Studio 文件解析](../../ksadk/studio/workspace.py#L75)、[工作区工具](../../ksadk/toolsets/workspace.py#L48)、[Harness 只读执行器](../../ksadk/harness/sandbox.py#L128)、[Codex 权限预设](../../ksadk/studio/codex_run.py#L456)。工程配置与构建 API 保持明确归属；对外目录通过任务文件访问层解析，不通过删除现有路径检查实现。普通 Python 工具或不受控子进程不能仅凭 Python 路径检查宣称受限，需后端执行约束；各 Runtime 分别报告并验证支持能力。

跨目录能力先完成适配验证，再承诺交付范围。Codex 先验证附加目录传递、模式和原生会话续接；Harness 先验证管理运行路径与工具隔离，不能简单将现有 `read_only` 改为 false（当前配置解析明确拒绝）。ADK/LangGraph 的用户自定义 Python 工具及外部 MCP 服务单列执行边界，不强行声称受本地文件策略约束；不支持某模式就明确显示，不静默改为完全访问。[Harness 配置限制](../../ksadk/harness/config.py#L160)

Bundle 的不可变是 SDK 的版本/完整性契约；工作区配置与关联操作不得改写既有制品。完全访问时外部命令仍可能修改磁盘文件，应沿用并补齐各 Runtime 加载前的制品校验，摘要不符时要求重新构建；不能承诺任意执行中的本地进程面对全盘写入仍有物理不可变性。[已有加载前校验](../../ksadk/studio/framework_run.py#L243)

Codex 官方将 `--cd`（默认目录）和 `--add-dir`（增加可写目录）分开，并提供完全访问沙箱模式。这支持上述概念拆分；本地完全访问的实际范围仍受 OS 约束。[OpenAI Docs CLI 参数](https://learn.chatgpt.com/docs/developer-commands?surface=cli)、[OpenAI Docs 沙箱模式](https://learn.chatgpt.com/docs/sandboxing)。本节是 KsADK 设计修订，不代表本轮已经执行 Runtime 权限实验。

## 7. 一期内部的架构选择与验证

| 方案 | 优点 | 主要代价 | 选择条件 |
|---|---|---|---|
| 单 Host 内按工作区注入服务上下文 | 进程少，资源共享充分；与 DSH 的方向接近 | 需清除环境变量、数据库路径、SDK 单例等隐式共享 | 所需 Runtime 全部通过双工作区隔离验证才可采用 |
| 一个入口，按需启动独立工作区 Worker | 可保留当前单 root StudioService，隔开旧环境桥接 | 需进程监管、认证代理、SSE 转发、回收与故障恢复 | 若单 Host 的环境隔离重构范围过大，作为一期过渡候选 |

**不提前拍板“每工作区必有一个进程”。** 先用两个假账号、两个不同目录和相同 Agent/Session ID 做架构实验，测配置污染、事件归属、内存和冷启动。采用哪种机制由验证结果决定，产品 API 不暴露进程差异。独立进程本身也不是同一 OS 用户下的文件安全沙箱。

这项实验在一期前段完成，用于确定工程路径，不用于再次决定是否做工作区切换。若两种候选都未通过必要验证，就继续修正实现并报告阻塞项，不能以退回单工作区配置功能宣称一期完成。

实验还需包含 A/B 使用不同 Python 虚拟环境、冲突依赖版本和同名本地模块的情形。明确哪个解释器加载 Agent、插件及构建工具；仅改变 cwd 或使用同一解释器启动两个 Worker，并不能解决项目依赖隔离。运行环境绑定属于工作区执行上下文，第一版需声明支持范围。

Worker 候选的约束：按需加载并限制数量，不为所有最近目录常驻进程；以干净启动快照加目标配置组装子进程环境，显式绑定数据库路径。跨端口 cookie 不能假设天然隔离；单入口代理需隔离 cookie、CSRF、路径与 SSE 重连游标。不能将 worker 端口、日志或内部管理令牌作为普通前端状态暴露。

关闭页面不等于终止工作区。活动任务、审批等待、构建部署、评测和启用的本地定时任务都应阻止无条件回收。当前调度器是本地 Studio 进程能力，若启用任务就应固定工作区进程存活，或另立持久调度器方案；不承诺关机后仍能执行。[现有调度器](../../ksadk/studio/scheduler_service.py#L29)

## 8. 实施顺序、产出和验收

### 8.1 产品分期

| 阶段 | 用户得到的能力 | 范围与完成标准 |
|---|---|---|
| **一期：完整本地工作流** | **全局配置 + 工作区切换 + 目录关联**；一个入口管理工程，当前任务可跨目录工作 | 三项一起验收；包含来源/继承、权限预设、后台状态/返回/取消、基础资源限制、失败可见性和安装包验证。只有其中一两项可用不算一期完成 |
| 二期：多项目工作体验增强 | 命名多账号连接、统一后台任务/审批中心、容量治理、可恢复任务的故障恢复、工作区收藏与整理 | 基于一期使用反馈细化；提升管理效率，不补做一期已承诺的切换与关联基本功能 |
| 三期：跨项目复用与任务接力 | Agent 模板/固定版本复用、关联目录模板、摘要与产物交接的新会话、按 Runtime 支持的目录重新定位 | 先明确资源重绑定、文件引用和恢复契约；不宣称复制会话就能迁移所有 checkpoint |
| 另行立项 | 云端/多租户工作区、平台级权限治理、活动 Session 跨 Runtime 迁移、通用 checkpoint 转换 | 需要独立业务场景、身份与执行边界设计，不作为前三期的隐含承诺 |

### 8.2 一期内部实施步骤

| 步骤 | 工程产出 | 完成条件 |
|---|---|---|
| 1. 契约与验证 | 配置字段归属、workspace/session 身份、目录访问策略；单 Host/Worker 及 Codex/Harness 适配实验 | 确定执行路径、权限生效点和 Runtime 支持表；产品三项范围保持不变 |
| 2. 全局配置 | 公共解析与写入服务、CLI 纠偏、用户默认/项目覆盖、来源与版本、迁移及生效状态 | 配置一次可供 A/B 使用；旧会话、计划和项目账号不随全局默认错误切换 |
| 3. 工作区管理 | 最近/打开/新建、稳定注册身份、请求/事件路由、按需运行上下文、标签页选择、后台状态入口 | 切到 B 时 A 保持归属并继续；可返回查看、审批或取消；不串历史或文件引用 |
| 4. 目录关联 | 参考目录和可写目录、本地访问模式、保存/移除关系、策略下发及状态、文件操作与子 Agent 适配 | A 中的 Agent 可按授权读取和修改 B 或普通目录，不切会话，不重复逐文件确认 |
| 5. 集成与交付验证 | 真实浏览器双项目流程、Runtime 请求链、并发/异常场景、静态资源与 wheel 安装验证 | 三项完整流程通过，声明的模式与实际能力一致，才标记一期完成 |

步骤用于组织提交和验证，允许配置、工作区路由、目录适配在契约明确后并行开发，不拆成三个独立产品期次。一期以 Codex 与 KsADK Harness 作为主要文件型 Agent 验收对象；现有 ADK/LangGraph 的配置和会话路由需兼容验证，自定义 Python 工具和外部 MCP 的访问边界按 6.1 节单列，不把 Runtime 名称当作文件隔离能力证明。

一期用户验收流程：启动 Studio → 保存用户默认连接 → 打开 A 并发起任务 → 为 A 关联 B/资料目录并按授权使用 → 切到 B 发起另一任务 → 从后台状态返回 A → 查看正确历史、实际文件变更与结果。刷新、重新启动和从 wheel 安装后，同一流程仍成立；重新启动时已有进行中任务按已声明的恢复能力显示状态，不承诺所有任务无损续跑。

不提供未经拆解的日历工期；一期包含三个互相关联的模块，实施估算在步骤 1 后给出。共享会话 UI 继续以 ksadk-web 为唯一实现来源，Studio 负责工程入口；不得复制一套聊天组件实现目录权限。执行阶段遵守隔离工作树与内部 master 评审流程；本计划不包含发布授权。

| 夹具 | 准备要求 |

| 连接 U/P | U 为用户默认、P 为 A 的项目覆盖。自动化测试使用可区分身份的假服务，记录接收身份标识；真实资源联调使用两个有权限的测试身份，凭据经受保护环境注入。证据只留脱敏标识，不留密钥 |
| 运行夹具 | 可持续至少 30 秒的流式任务、等待审批任务、可控失败任务、写入测试标记的幂等工具、可取消的子进程任务，以及一个现有本地定时任务 |
| 归属碰撞 | 在测试存储中为 A/B 准备相同 Agent/Session ID，内容和文件标记不同；由测试夹具生成合法记录，不要求用户 UI 提供自定义内部 ID 功能 |
| 旧配置样本 | 现有全局 settings.json、项目 canonical 配置、两类 legacy 配置、工程声明和应用 `.env`，包含可识别的未知字段/注释；全部是假数据。保存操作前后记录文件摘要及脱敏语义差异 |
| 安装候选 | 固定 KsADK 源码 SHA、共享 Web 源码/包版本和静态资源摘要；从该候选构建 wheel 并记录 SHA256。源码目录不在安装验收的 Python 搜索路径内 |

验收基准建议并默认采用 macOS arm64、Python 3.11、本地 SSD、至少 4 个逻辑 CPU/16 GiB 内存；报告记录实际 OS、硬件和依赖版本。Linux x86_64/Python 3.11 作为第二个完整功能验证环境。Python 版本与 OS 常规兼容继续执行仓库既有 CI；新增配置模块至少在项目声明的最低 Python 3.10 与 3.11 上运行相关测试。这些是验收基线，不是新增 SDK 最低硬件或 Python 要求。

| 验收维度 | 一期必测内容 | 不允许的替代 |
|---|---|---|
| Codex / KsADK Harness | 在上述两个完整验证平台分别跑配置、切换、目录关联、主 E2E；至少验证本地开发与本地完全访问两种模式，均应支持关联目录实际读写 | 只验证 Codex、只展示 Harness 菜单，或用假 Runtime 代替真实执行 |

步骤 1 结束时提交准确的 OS/Runtime/模式支持表和启动依赖清单。Codex/Harness 的两种必测模式、三项一期功能及旧运行兼容不能由实现者自行标记 `N/A`；若无法满足，记录阻塞项并完成设计调整，不能在验收时缩小口径。

证据类型统一为：**V** 真实浏览器录像/截图及脱敏网络记录；**R** 服务/Runtime 记录（工作区、Agent、Session、Run、配置/授权版本和身份标识）；**F** 测试文件、存储快照及差异；**T** 自动化测试命令、结果和失败日志；**A** 制品 SHA、静态资源摘要、安装位置及实际 CLI 路径。每条用例至少保留表内要求的证据，HTTP 200 或模型口头声称成功不单独算通过。

E2E-01 在 Codex 和 KsADK Harness 上分别执行，不能以一次通用前端录像覆盖两个 Runtime。E2E-02 至少一次经过真实测试身份与资源准入服务，假身份服务用于全面冲突覆盖。每个主 Runtime 的主流程独立成功 3 次并留存各 Run 标识；出现失败先定位，最终候选上的通过记录与修复关联，不通过删掉失败记录获得“全绿”。

### 8.6 可用性、性能与资源目标

以下数值是一期的设计验收目标，不是已经测得的结果。测试使用 8.3 的数据规模和参考机，记录实际环境；模型响应时间、首次依赖下载安装不计入工作区页面切换耗时，但必须独立展示进度，不能把空白页或长时间冻结算作可用。

| 编号 | 测量操作 | 通过标准 | 证据 |
|---|---|---|---|
| UX-01 | 展示当前工作区、连接来源、关联有效权限及后台状态；在 1,280 × 800 的桌面浏览器走主流程 | 路径/项目有明确标识；保存目标和生效状态可辨认；关键按钮不被遮挡；授权、运行和异常状态不只靠颜色表达；已授权重复文件操作 0 次多余权限确认 | V/T |
| PERF-01 | A/B 已加载后交替切换 30 次，从用户操作计时到目标工作区标识和主体列表可交互 | p95 ≤ 1 秒；30 次归属均正确；无整页服务重启。需同时记录样本数和 p50/p95/max，不能只提供最快一次 | V/T |

### 8.7 通过规则与验收记录

验收采用 `NOT_RUN / PASS / FAIL / BLOCKED / N/A` 五种状态。默认全部 `NOT_RUN`；缺少模型服务、测试身份、平台或证据为 `BLOCKED`，不是通过。`N/A` 必须说明用例里的哪条适用条件不成立，不能用于省略三项一期功能或两个主 Runtime 的必测组合。

放行规则：G1–G6 全部达成；适用的 CFG/WS/DIR/PKG/E2E/UX/PERF/RES 用例全部 PASS；主链路和支持表有真实证据；不存在 S0/S1 问题。S0 指数据破坏、错误身份执行或未授权访问；S1 指三项功能/主 Runtime/安装升级不可用、归属错误、必测目标或必需检查不通过。S2 为不影响验收目标的文案或局部布局问题，需记录负责人、影响和后续安排，不能把 S1 改名为 S2 绕过放行。

单测、浏览器、真实 Runtime、候选包安装、正式 registry 安装分别列结果。最终候选 SHA 或静态资源变化后，受影响用例与制品检查重新执行；不得拼接不同候选的结果宣称同一候选全部通过。

## 9. 最终产品口径

用户只需理解：“我在某个项目里使用某个 Agent，可以关联其他目录；常用连接属于我，项目可以覆盖；文件访问范围由我选择，任务始终知道自己属于哪个项目。”

预期价值是减少重复配置、减少开终端切目录、正确返回历史任务。进程数、Worker、配置文件数量与框架选择是实现细节，不作为面向用户的功能卖点。跨目录访问、任务接力和企业隔离分别按其实际需求设计，不以一个“动态工作空间”开关包办。
