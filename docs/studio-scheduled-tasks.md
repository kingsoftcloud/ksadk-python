# Studio 定时任务与任务看板

本地 Studio 支持从智能体对话或「自动化」页面安排重复工作。任务保存在当前工作区，
到期后通过现有 Scheduler、AgentControl 和 Agent Kernel 执行，结果保存在会话历史中。

## 在对话中安排任务

选择本地智能体后，可以直接输入：

- 每天 10 点帮我生成昨日工作日报。
- 每 7 分钟帮我检查服务状态。
- 每周五下午 5 点整理一份周报。
- 查看我的定时任务。
- 暂停定时任务「每日简报」。
- 把定时任务「每日简报」改为工作日早上 9 点。

明确的定时请求会调用 Studio 的 `studio_schedule` 管理工具。成功回复来自实际保存结果，
包含计划、时区、下次执行时间和任务标识；不会把普通回复当成已创建任务。
时间或任务内容不明确时会要求补充，在同一会话中可以继续回答。
解释 Cron、编写定时脚本示例、否定创建等消息继续交给原智能体处理。

默认时区为 `Asia/Shanghai`，周期任务错过时跳过，每次执行新建会话。
只有用户明确要求继续当前会话时才绑定当前会话，并检查归属和运行时的续接能力。
固定间隔按实际秒数保存，因此每 7 分钟是真正的 7 分钟间隔。

## 在界面中管理

- 看板按「待执行、执行中、需关注、已暂停 / 已结束」分组，也可以切换列表、搜索或筛选智能体。
- 通过每日简报、定期巡检、每周总结模板快速建立任务，再修改任务说明。
- 固定时间支持每天、工作日、每周；高级场景可以填写 Cron。
- 固定间隔支持分钟、小时和天；单次任务按所选时区解析，避免浏览器时区改变执行时间。
- 详情中可以编辑、暂停、启用、立即运行、删除，并从执行记录打开实际会话阅读结果。
- 继续已有会话使用选择器；不需要手工复制 Session ID。

列表与看板定期刷新，任务的状态摘要独立于最近 200 条执行记录，避免高频任务淹没其他任务的失败状态。
「执行中」优先展示仍在运行的记录，较新的重叠跳过记录不会掩盖它。

## 执行边界

这是本地工作区的调度：**Studio 与设备需要保持运行**，当前改动不提供云端常驻调度。
同一任务已有执行在进行时，重叠触发会跳过。任务删除后保留执行历史。
暂停的任务需要先启用才能立即运行；过期的单次任务需要修改时间才能重新启用。
执行计划绑定创建时的构建版本，编辑提示词或时间不会悄悄更换该版本。

## 实现与验证入口

- `ksadk/studio/scheduler_assistant.py`：本地会话的调度管理能力。模型只能提交意图，
  Agent、Build、Kernel、授权引用和当前会话由 Studio 决定；操作已有任务必须校验 Agent 归属。
- `ksadk/studio/run_service.py`：在各本地运行时分流前接入，保留标准运行记录、工具回执和会话事件。
  此入口不修改用户编译的 graph，也不影响云端对话代理。
- `ksadk/studio/react-ui/src/pages/AutomationsPage.tsx` 与 `AutomationEditor.tsx`：Studio 管理页面。
  对话渲染及会话加载继续消费 `ksadk-web`，Studio 负责结果会话的导航。
- `ksadk/studio/shared_web.py`：将定时执行的 canonical 会话事件投影到现有历史接口，
  包括与人工追问混合的会话；不创建重复的运行记录或另一套对话渲染。
- `tests/studio/test_scheduler_assistant.py`：真实任务保存、到期执行、跨 Agent 拒绝、取消和会话回执。
- `tests/studio/e2e/scheduler_harness_browser_e2e.py`：实际浏览器、HTTP、生产模型客户端、SQLite、Kernel 与 Harness；
  仅外部模型响应使用确定性服务。覆盖对话创建、看板、编辑器与结果会话。
- `tests/studio/e2e/scheduler_browser_e2e.py`：Codex 原生执行及已有会话续接。
- `tests/studio/e2e/scheduler_fault_matrix_browser_e2e.py`：失败、超时、恢复及跳过等执行记录。

设置 `KSADK_SCHEDULER_E2E_ARTIFACT_DIR` 后，Harness 浏览器验证会保存看板、编辑器和结果页截图。
真实模型的自然语言解析仍需独立验证；确定性模型服务只证明执行契约和界面链路。
