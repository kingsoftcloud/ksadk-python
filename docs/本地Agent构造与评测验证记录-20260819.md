## 4. 各框架 Agent 形态

### 4.1 ADK

文件：

```text
tmp/local-agent-framework-eval-20260819/adk/agent.py
```

形态：

- 使用 `google.adk.agents.Agent`
- 使用继承 `BaseLlm` 的本地确定性模型
- 顶层暴露 `root_agent`
- 固定返回 `ADK_LOCAL_OK`

关键代码结构：

```python
class DeterministicLlm(BaseLlm):
    async def generate_content_async(self, llm_request, stream=False):
        yield partial_response("ADK_LOCAL_OK")
        yield final_response("ADK_LOCAL_OK")

root_agent = Agent(
    name="local_adk_eval",
    model=DeterministicLlm(model="deterministic-local"),
    instruction="Return the deterministic validation response.",
)
```

### 4.2 LangChain

文件：

```text
tmp/local-agent-framework-eval-20260819/langchain/agent.py
```

形态：

- 使用 LangChain 原生 `create_agent`
- 使用 `FakeListChatModel`，避免外部模型调用
- 顶层暴露 `root_agent`
- 固定返回 `LANGCHAIN_LOCAL_OK`

```python
model = FakeListChatModel(responses=["LANGCHAIN_LOCAL_OK"])
root_agent = create_agent(
    model=model,
    tools=[],
    system_prompt="Return the deterministic validation response.",
)
```

当前 Local Source 适配器将 LangChain 运行时归一为 `langgraph`，但 snapshot 中仍保留 `detectedFramework: langchain`。

### 4.3 LangGraph

文件：


形态：

- 使用 `StateGraph(dict)`
- 编译结果通过 `root_agent` 暴露

### 4.4 DeepAgents

文件：

```text
tmp/local-agent-framework-eval-20260819/deepagents/agent.py
```

形态：

- 使用 `create_deep_agent`
- 使用本地 `FakeListChatModel`
- 测试模型覆盖 `bind_tools`
- 顶层暴露 `root_agent`
- 固定返回 `DEEPAGENTS_LOCAL_OK`

DeepAgents middleware 即使没有业务工具，也会调用模型的 `bind_tools`。因此 fixture 使用了：

```python
class DeterministicChatModel(FakeListChatModel):
    def bind_tools(self, tools, **kwargs):
        return self
```

当前实现将 DeepAgents 运行时归一为 `langgraph`。

## 5. EvalSet

每个目录有独立 `suite.yaml`，都使用一个确定性 case 和 `response.contains` 断言。例如：

```yaml
schemaVersion: ksadk.eval/v1
name: local-langgraph-evalset
cases:
  - id: deterministic-langgraph
    input: "return the validation marker"
    assertions:
      - type: response.contains
        value: LANGGRAPH_LOCAL_OK
```

选择关键词断言而不是完整自然语言匹配，是为了让验证关注运行时闭环，不受模型措辞影响。

## 8. 首次失败和修正过程

### 8.1 ADK 首次运行

首次 ADK 评测报告状态为 `FAILED`，TargetRun 为 `UNAVAILABLE`：

```text
errorCode: LOCAL_OUTPUT_UNAVAILABLE
errorMessage: Local Agent did not provide evaluable text output
```

但 evidence 已经包含：

- `run.started`
- `turn.started`
- `text.completed`
- `turn.completed`
- `run.completed`

初始 fake model 只产生了 `partial=False` 的最终响应。当前 ADK 流式语义事件路径只从 partial 响应累积文本，导致 RuntimeEvent 存在但评测输出为空。

修正方式：fake model 同时产生 partial 文本和 final 文本。修正后 ADK 评测通过。

这说明真实 ADK 模型接入时需要验证：

- streaming 事件是否带文本；
- partial/final 事件是否符合当前 ADKRunner 解析逻辑；
- 最终 completion 是否能进入 `output_text`。

### 8.2 DeepAgents 首次运行

首次 DeepAgents 评测报告状态为 `ERROR`：

```text
errorCode: LOCAL_RUNTIME_ERROR
errorMessage: Local Agent runtime failed
```

直接调用得到的底层异常是：

```text
NotImplementedError: BaseChatModel.bind_tools
```

DeepAgents middleware 会绑定工具，即使 fixture 没有业务工具。普通 `FakeListChatModel` 没有实现 `bind_tools`，因此运行失败。

修正方式：使用一个覆盖 `bind_tools` 并返回自身的测试模型。修正后 DeepAgents 评测通过。

这说明真实 DeepAgents Agent 的模型必须支持工具绑定能力，不能只验证普通 `invoke`。

### 8.3 首次失败时 CLI 退出码观察

首次 ADK 和 DeepAgents 报告虽然分别为 `FAILED`/`ERROR`，但 PowerShell 中 `agentengine.exe eval` 的进程退出码仍为 0。最终四次通过评测的退出码也为 0。

因此当前验证自动化不能只依赖进程退出码，还应解析：

```text
report.json.status
caseRuns[].targetRun.status
metrics[].status
```

这是 CLI 失败状态退出码传播值得后续确认的实现问题。

## 9. 当前边界

本次验证证明的是：

- 四类框架可以被当前 Detector 识别；
- 四类 Agent 都能通过当前 Local Source Runtime 链路执行；
- LangChain/DeepAgents 可以复用 LangGraph Runtime；
- session、invocation、RuntimeEvent、TraceRef、evidence 和报告合同能够闭环；
- 确定性 fixture 不需要真实模型凭据。

本次没有证明：

- 真实 OpenAI-compatible 模型调用；
- 网络异常、模型超时、token usage；
- 知识库召回和外部工具副作用；
- 多轮记忆、checkpoint resume；
- Hermes/OpenClaw/FastMCP 的 Local Source 评测；
- 远端 A2A 或 Studio Build 评测。

这些场景应分别使用真实模型环境、A2A Target 或 Studio Build Target 验证。

## 10. 后续建议

1. 将这四类 fixture 保留为本地 smoke 验证样例，并为每个 fixture 增加多轮 case。
2. 增加真实模型 profile：使用环境变量提供凭据，断言改为事实/结构/关键词。
3. 增加一个带工具的 LangGraph/DeepAgents fixture，验证 ToolCallEvidence 和工具轨迹指标。
4. 修正或明确 CLI 在报告失败时的退出码语义，自动化脚本必须解析报告状态。
5. 对 ADK 增加 partial/final 流式输出回归测试，避免 RuntimeEvent 有文本而 `TargetRun.output` 为空。
6. 将 fixture 的依赖版本锁定，记录模型、SDK、EvalSet content digest，提升跨机器复现能力。
