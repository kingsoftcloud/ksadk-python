# 运行响应耗时字段

本变更增加可选响应字段 `timing`，与 `usage`、`output_text` 同级；不改变模型消息或 Token 汇总。适用于当前 RunnerRuntimeAdapter / LangGraph 运行路径的 `/v1/responses` 和 Responses 格式的 `RunAgent`。非流式 JSON 与 SSE `response.completed` 使用同一来源。

## 字段与口径

所有数值单位为毫秒，可为小数。字段名固定包含 `_duration_ms`。

| 字段 | 所有者 | 口径 |
| --- | --- | --- |
| agent_duration_ms | KsADK | runner 输入准备完成后，执行 runner 并转发运行事件，直到本次运行终态的墙钟耗时。包含该区间内框架和事件处理开销；不包含平台排队、会话预处理、客户端网络或部署冷启动。不能直接等同于 Trace root 或 HTTP 总耗时。 |
| selection_duration_ms | Agent | 实际模型选择阶段，包含请求准备、模型调用和选择结果解析。强制选择跳过该阶段。 |
| answer_duration_ms | Agent | 回答生成阶段；评测激活后的三个回答入口采用同一字段。 |
| skill_load_duration_ms | Agent | 外层加载所选 Skill 的阶段。 |
| skill_execution_duration_ms | Agent | 外层执行节点阶段，包含调用运行时、等待和接收结果。多个执行项累计；不是纯脚本时间，也不是 Sandbox backend 的 duration_ms。 |

阶段值不相加生成整体值。阶段明细未覆盖候选集处理、编排、最终结果整理等全部开销；嵌套或并行阶段也不能机械相加。

`phase_status` 使用 `agent`、`selection`、`answer`、`skill_load`、`skill_execution` 作为键：

- `measured`：有非负有限数值，0 是有效测量。阶段业务失败但耗时已测得时仍是 measured；业务状态继续使用执行结果。
- `skipped`：确认未执行，数值为 null。
- `unavailable`：未取得有效测量，数值为 null。不会用 0 代替缺失。

旧 Agent 不提供阶段明细时，SDK 只新增自己测量的整体耗时，不推测阶段值。旧 runtime 未提供 timing 时，Responses payload 不新增空 timing。硬异常仍沿现有错误协议返回，不伪造成功完成响应；本变更不承诺硬异常 HTTP 响应一定携带阶段明细。中断续跑不是跨调用累计账本，本版服务于一次完整评测调用。

## 传递链路

Base Agent 每次新评测初始化独立 `timing` 状态。节点通过轻量计时包装记录阶段，最终 state 保留数据，不拼入回答或 skill_eval_result。

LangGraph runner 只提取根图最终状态的 timing（直接 invoke 从返回状态提取），不会从模型消息、工具输出或嵌套子图内容推断耗时。最终 chunk 的 timing 进入 `completion_metrics.timing`，运行层写入独立计算的 agent_duration_ms。RunCompleted 的 `source.metadata.metrics.timing` 传递给 semantic completed 事件，再进入普通响应收集器及流式 Responses 构造器。

SDK 只接受约定字段及有限非负数值。Agent 提供的整体耗时会由 SDK 自己的测量覆盖。所有阶段数据按本次调用传递，不从请求 metadata 回填。

平台 RunSkillEvaluation 现有的响应投影使用原 payload 扩展，因此可以保留 SDK 的顶层 timing，无需将其加入 Skill 结果后缀。线上需要在 Agent 构建交付中同时包含本次 Agent 与 SDK 改动；仅更新本地源码不会改变已部署实例。没有更改依赖版本号、发布或部署。

## 本次验证

使用 KsADK 项目的 `.venv/bin/python`，Base Agent 测试通过 PYTHONPATH 加载本地 Agent 源码与本地 SDK：

- Base Agent `tests`：31 passed。
- SDK 的 conversation execution、Responses streaming、timing、LangGraph observability/projection/resume、server session app：218 passed。
- 本地 HTTP 联调使用真实 Base Agent 图、LangGraph runner、runtime adapter 和 Responses 路由，模型以可流式输出的测试模型替代；同时验证 Stream=false/true，未调用线上模型或 Skill 服务。
- 独立代码审查未发现本次评测路径上的阻塞问题。
- 本次修改的 SDK 生产代码及新增 timing 测试通过 Ruff；`test_server_session_app.py` 原有两处 lint 问题经 HEAD 对照确认未新增。

部署后于 2026-09-08 完成预发验证：9 次 RunSkillEvaluation 调用及对应 9 条 trace 核对通过，覆盖 no_skill、forced_skill、auto_select、指令型与脚本型 Skill，以及普通响应与流式完成响应。Token（含缓存和推理）与 trace 汇总一致，22 项阶段耗时比较的最大绝对差为 5.166 ms。未覆盖云端超时、中断、多 Skill 顺序执行和 checkpoint 恢复。
